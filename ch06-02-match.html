The Rust Programming Language

Konstruksi Alur Kontrol match

Rust memiliki konstruksi alur kontrol yang sangat powerful bernama match yang memungkinkan Anda membandingkan nilai terhadap serangkaian pola dan kemudian menjalankan kode berdasarkan pola mana yang cocok. Pola bisa terdiri dari nilai literal, nama variabel, wildcard, dan banyak hal lain; Bab 19 membahas semua jenis pola yang berbeda dan apa yang mereka lakukan. Kekuatan match berasal dari ekspresivitas pola dan fakta bahwa compiler memastikan bahwa semua kasus mungkin ditangani.

Bayangkan ekspresi match seperti mesin penyortir koin: Koin meluncur ke bawah trek dengan lubang berukuran berbagai di sepanjangnya, dan setiap koin jatuh melalui lubang pertama yang ia temui yang cocok dengannya. Dengan cara yang sama, nilai melewati setiap pola di match, dan pada pola pertama yang nilainya “cocok,” nilai itu jatuh ke dalam blok kode terkait untuk digunakan selama eksekusi.

Bicara soal koin, mari gunakan mereka sebagai contoh menggunakan match! Kami bisa menulis fungsi yang mengambil koin AS tidak diketahui dan, dengan cara mirip mesin penghitung, menentukan koin apa itu dan mengembalikan nilainya dalam sen, seperti yang ditunjukkan di Listing 6-3.

Mari uraikan match di fungsi value_in_cents. Pertama, kami mencantumkan kata kunci match diikuti oleh ekspresi, yang dalam kasus ini adalah nilai coin. Ini terlihat sangat mirip dengan ekspresi kondisional yang digunakan dengan if, tapi ada perbedaan besar: Dengan if, kondisi harus mengevaluasi ke nilai Boolean, tapi di sini bisa tipe apa pun. Tipe coin dalam contoh ini adalah enum Coin yang kami definisikan di baris pertama.

Selanjutnya adalah arm (lengan) match. Sebuah arm memiliki dua bagian: pola dan beberapa kode. Arm pertama di sini memiliki pola yang adalah nilai Coin::Penny dan kemudian operator => yang memisahkan pola dan kode yang akan dijalankan. Kode dalam kasus ini hanyalah nilai 1. Setiap arm dipisahkan dari yang berikutnya dengan koma.

Saat ekspresi match dieksekusi, ia membandingkan nilai hasil dengan pola setiap arm, secara berurutan. Jika pola cocok dengan nilai, kode yang terkait dengan pola itu dieksekusi. Jika pola itu tidak cocok dengan nilai, eksekusi berlanjut ke arm berikutnya, mirip seperti mesin penyortir koin. Kami bisa memiliki arm sebanyak yang dibutuhkan: Di Listing 6-3, match kami memiliki empat arm.

Kode yang terkait dengan setiap arm adalah ekspresi, dan nilai hasil ekspresi di arm yang cocok adalah nilai yang dikembalikan untuk seluruh ekspresi match.

Kami biasanya tidak menggunakan tanda kurung kurawal jika kode arm match pendek, seperti di Listing 6-3 di mana setiap arm hanya mengembalikan nilai. Jika Anda ingin menjalankan beberapa baris kode di arm match, Anda harus menggunakan tanda kurung kurawal, dan koma setelah arm itu menjadi opsional. Misalnya, kode berikut mencetak “Lucky penny!” setiap kali metode dipanggil dengan Coin::Penny, tapi tetap mengembalikan nilai terakhir blok, 1:

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => {
            println!("Lucky penny!");
            1
        }
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter => 25,
    }
}

fn main() {}

Pola yang Mengikat ke Nilai

Fitur berguna lain dari arm match adalah mereka bisa mengikat ke bagian-bagian nilai yang cocok dengan pola. Inilah cara kita mengekstrak nilai keluar dari varian enum.

Sebagai contoh, mari ubah salah satu varian enum kami untuk menampung data di dalamnya. Dari 1999 hingga 2008, Mencetak AS mencetak quarter dengan desain berbeda untuk masing-masing 50 negara bagian di satu sisi. Koin lain tidak mendapat desain negara bagian, jadi hanya quarter yang memiliki nilai tambahan ini. Kami bisa menambahkan informasi ini ke enum kami dengan mengubah varian Quarter untuk menyertakan nilai UsState yang disimpan di dalamnya, yang kami lakukan di Listing 6-4.

Bayangkan seorang teman mencoba mengumpulkan semua 50 quarter negara bagian. Saat kami mengurutkan uang kembalian kami berdasarkan jenis koin, kami juga akan menyebut nama negara bagian yang terkait dengan setiap quarter sehingga jika itu yang belum dimiliki teman kami, mereka bisa menambahkannya ke koleksi mereka.

Di ekspresi match untuk kode ini, kami menambahkan variabel bernama state ke pola yang mencocokkan nilai varian Coin::Quarter. Saat Coin::Quarter cocok, variabel state akan terikat ke nilai negara bagian quarter itu. Kemudian, kami bisa menggunakan state di kode untuk arm tersebut, seperti begini:

#[derive(Debug)]
enum UsState {
    Alabama,
    Alaska,
    // --snip--
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter(UsState),
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter(state) => {
            println!("State quarter from {state:?}!");
            25
        }
    }
}

fn main() {
    value_in_cents(Coin::Quarter(UsState::Alaska));
}

Jika kami memanggil value_in_cents(Coin::Quarter(UsState::Alaska)), coin akan menjadi Coin::Quarter(UsState::Alaska). Saat kami membandingkan nilai itu dengan setiap arm match, tidak ada yang cocok hingga kami mencapai Coin::Quarter(state). Pada titik itu, pengikatan untuk state akan menjadi nilai UsState::Alaska. Kami kemudian bisa menggunakan pengikatan itu di ekspresi println!, dengan demikian mendapatkan nilai state di dalamnya dari varian enum Coin untuk Quarter.

Pola match Option<T>

Di bagian sebelumnya, kami ingin mendapatkan nilai T di dalamnya dari kasus Some saat menggunakan Option<T>; kami juga bisa menangani Option<T> menggunakan match, seperti yang kami lakukan dengan enum Coin! Alih-alih membandingkan koin, kami akan membandingkan varian Option<T>, tapi cara ekspresi match bekerja tetap sama.

Katakanlah kami ingin menulis fungsi yang mengambil Option<i32> dan, jika ada nilai di dalamnya, menambahkan 1 ke nilai itu. Jika tidak ada nilai di dalamnya, fungsi harus mengembalikan nilai None dan tidak mencoba melakukan operasi apa pun.

Fungsi ini sangat mudah ditulis, berkat match, dan akan terlihat seperti Listing 6-5.

Mari periksa eksekusi pertama plus_one lebih detail. Saat kami memanggil plus_one(five), variabel x di badan plus_one akan memiliki nilai Some(5). Kami kemudian membandingkan itu dengan setiap arm match:

fn main() {
    fn plus_one(x: Option<i32>) -> Option<i32> {
        match x {
            None => None,
            Some(i) => Some(i + 1),
        }
    }

    let five = Some(5);
    let six = plus_one(five);
    let none = plus_one(None);
}

Nilai Some(5) tidak cocok dengan pola None, jadi kami lanjut ke arm berikutnya:

fn main() {
    fn plus_one(x: Option<i32>) -> Option<i32> {
        match x {
            None => None,
            Some(i) => Some(i + 1),
        }
    }

    let five = Some(5);
    let six = plus_one(five);
    let none = plus_one(None);
}

Apakah Some(5) cocok Some(i)? Cocok! Kami memiliki varian yang sama. i terikat ke nilai yang terkandung di Some, jadi i mengambil nilai 5. Kode di arm match kemudian dieksekusi, jadi kami menambahkan 1 ke nilai i dan membuat nilai Some baru dengan total 6 di dalamnya.

Sekarang mari pertimbangkan pemanggilan kedua plus_one di Listing 6-5, di mana x adalah None. Kami masuk ke match dan bandingkan ke arm pertama:

fn main() {
    fn plus_one(x: Option<i32>) -> Option<i32> {
        match x {
            None => None,
            Some(i) => Some(i + 1),
        }
    }

    let five = Some(5);
    let six = plus_one(five);
    let none = plus_one(None);
}

Itu cocok! Tidak ada nilai untuk ditambahkan, jadi program berhenti dan mengembalikan nilai None di sisi kanan =>. Karena arm pertama cocok, arm lain tidak dibandingkan.

Menggabungkan match dan enum berguna dalam banyak situasi. Anda akan melihat pola ini banyak di kode Rust: match terhadap enum, ikat variabel ke data di dalam, dan kemudian eksekusi kode berdasarkan itu. Agak tricky di awal, tapi begitu Anda terbiasa, Anda akan berharap punya ini di semua bahasa. Ini konstanta menjadi favorit pengguna.

Match Harus Exhaustive (Menyingkirkan Semua Kemungkinan)

Ada aspek lain match yang perlu kami bahas: Pola arm harus menutupi semua kemungkinan. Pertimbangkan versi fungsi plus_one kami ini, yang memiliki bug dan tidak akan kompilasi:

fn main() {
    fn plus_one(x: Option<i32>) -> Option<i32> {
        match x {
            Some(i) => Some(i + 1),
        }
    }

    let five = Some(5);
    let six = plus_one(five);
    let none = plus_one(None);
}

Kami tidak menangani kasus None, jadi kode ini akan menyebabkan bug. Untungnya, ini bug yang Rust tahu cara menangkapnya. Jika kami mencoba mengompilasi kode ini, kami akan mendapat kesalahan ini:

Rust tahu bahwa kami tidak menutupi setiap kasus mungkin dan bahkan tahu pola mana yang kami lupakan! Match di Rust exhaustive (menyingkirkan semua kemungkinan): Kami harus menyingkirkan setiap kemungkinan terakhir agar kode valid. Khususnya dalam kasus Option<T>, saat Rust mencegah kami melupakan penanganan eksplisit kasus None, ia melindungi kami dari mengasumsikan bahwa kami memiliki nilai saat kami mungkin null, dengan demikian membuat kesalahan miliar dolar yang dibahas sebelumnya menjadi mustahil.

Pola Catch-All dan Placeholder _

Menggunakan enum, kami juga bisa mengambil aksi khusus untuk beberapa nilai khusus, tapi untuk semua nilai lain mengambil satu aksi default. Bayangkan kami mengimplementasikan game di mana, jika Anda melempar 3 pada lemparan dadu, pemain Anda tidak bergerak tapi malah mendapatkan topi baru yang fancy. Jika Anda melempar 7, pemain Anda kehilangan topi fancy. Untuk semua nilai lain, pemain Anda bergerak sejumlah ruang pada papan game. Berikut match yang mengimplementasikan logika itu, dengan hasil lemparan dadu di-hardcode bukannya nilai acak, dan semua logika lain diwakili oleh fungsi tanpa badan karena benar-benar mengimplementasikannya di luar cakupan untuk contoh ini:

fn main() {
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        other => move_player(other),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
    fn move_player(num_spaces: u8) {}
}

Untuk dua arm pertama, pola adalah nilai literal 3 dan 7. Untuk arm terakhir yang menutupi setiap nilai mungkin lain, pola adalah variabel yang kami pilih namakan other. Kode yang berjalan untuk arm other menggunakan variabel dengan meneruskannya ke fungsi move_player.

Kode ini kompilasi, meskipun kami belum mencantumkan semua nilai mungkin yang bisa dimiliki u8, karena pola terakhir akan cocok dengan semua nilai yang tidak secara khusus dicantumkan. Pola catch-all ini memenuhi persyaratan bahwa match harus exhaustive. Perhatikan bahwa kami harus menaruh arm catch-all terakhir karena pola dievaluasi berurutan. Jika kami menaruh arm catch-all lebih awal, arm lain tidak akan pernah berjalan, jadi Rust akan memperingatkan kami jika kami menambahkan arm setelah catch-all!

Rust juga memiliki pola yang bisa kami gunakan saat kami ingin catch-all tapi tidak ingin menggunakan nilai di pola catch-all: _ adalah pola khusus yang cocok dengan nilai apa pun dan tidak mengikat ke nilai itu. Ini memberitahu Rust bahwa kami tidak akan menggunakan nilai itu, jadi Rust tidak akan memperingatkan tentang variabel yang tidak digunakan.

Mari ubah aturan game: Sekarang, jika Anda melempar selain 3 atau 7, Anda harus melempar lagi. Kami tidak lagi butuh nilai catch-all, jadi kami bisa mengubah kode kami untuk menggunakan _ sebagai gantinya variabel bernama other:

fn main() {
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        _ => reroll(),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
    fn reroll() {}
}

Contoh ini juga memenuhi persyaratan exhaustiveness karena kami secara eksplisit mengabaikan semua nilai lain di arm terakhir; kami tidak melupakan apa pun.

Akhirnya, kami akan mengubah aturan game sekali lagi sehingga tidak ada apa pun yang terjadi pada giliran Anda jika Anda melempar selain 3 atau 7. Kami bisa mengekspresikan itu dengan menggunakan nilai unit (tipe tuple kosong yang kami sebutkan di bagian “Tipe Tuple”) sebagai kode yang pergi dengan arm _:

fn main() {
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        _ => (),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
}

Di sini, kami secara eksplisit memberitahu Rust bahwa kami tidak akan menggunakan nilai lain yang tidak cocok dengan pola di arm sebelumnya, dan kami tidak ingin menjalankan kode apa pun dalam kasus ini.

Ada lebih banyak tentang pola dan pencocokan yang akan kami bahas di Bab 19. Untuk sekarang, kami akan lanjut ke sintaks if let, yang bisa berguna dalam situasi di mana ekspresi match agak bertele-tele.
