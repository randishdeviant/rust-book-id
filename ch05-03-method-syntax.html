The Rust Programming Language

Metode

Metode mirip dengan fungsi: Kami mendeklarasikannya dengan kata kunci fn dan nama, mereka bisa memiliki parameter dan nilai kembali, dan mereka berisi kode yang dijalankan saat metode dipanggil dari tempat lain. Berbeda dengan fungsi, metode didefinisikan dalam konteks struct (atau enum atau trait object, yang kami bahas di Bab 6 dan Bab 18, masing-masing), dan parameter pertama mereka selalu self, yang mewakili instance struct yang metode dipanggil padanya.

Sintaks Metode

Mari ubah fungsi area yang memiliki instance Rectangle sebagai parameter dan sebaliknya buat metode area yang didefinisikan pada struct Rectangle, seperti yang ditunjukkan di Listing 5-13.

Untuk mendefinisikan fungsi dalam konteks Rectangle, kami memulai blok impl (implementasi) untuk Rectangle. Semua di dalam blok impl ini akan terkait dengan tipe Rectangle. Kemudian, kami memindahkan fungsi area ke dalam tanda kurung kurawal impl dan mengubah parameter pertama (dan dalam kasus ini, satu-satunya) menjadi self di tanda tangan dan di mana pun di dalam badan. Di main, di mana kami memanggil fungsi area dan meneruskan rect1 sebagai argumen, kami bisa menggunakan sintaks metode untuk memanggil metode area pada instance Rectangle kami. Sintaks metode pergi setelah instance: Kami menambahkan titik diikuti nama metode, tanda kurung, dan argumen apa pun.

Di tanda tangan untuk area, kami menggunakan &self alih-alih rectangle: &Rectangle. &self sebenarnya adalah singkatan untuk self: &Self. Di dalam blok impl, tipe Self adalah alias untuk tipe yang blok impl itu. Metode harus memiliki parameter bernama self bertipe Self untuk parameter pertama mereka, jadi Rust membiarkan Anda mengabbreviasi ini hanya dengan nama self di tempat parameter pertama. Perhatikan bahwa kami masih perlu menggunakan & di depan singkatan self untuk menunjukkan bahwa metode ini meminjam instance Self, seperti yang kami lakukan di rectangle: &Rectangle. Metode bisa mengambil kepemilikan self, meminjam self secara immutable, seperti yang kami lakukan di sini, atau meminjam self secara mutable, sama seperti parameter lain.

Kami memilih &self di sini untuk alasan yang sama kami menggunakan &Rectangle di versi fungsi: Kami tidak ingin mengambil kepemilikan, dan kami hanya ingin membaca data di struct, bukan menulis ke dalamnya. Jika kami ingin mengubah instance yang kami panggil metodenya sebagai bagian dari apa yang dilakukan metode, kami akan menggunakan &mut self sebagai parameter pertama. Memiliki metode yang mengambil kepemilikan instance dengan hanya menggunakan self sebagai parameter pertama jarang; teknik ini biasanya digunakan saat metode mentransformasi self menjadi sesuatu yang lain dan Anda ingin mencegah pemanggil dari menggunakan instance asli setelah transformasi.

Alasan utama menggunakan metode bukannya fungsi, selain menyediakan sintaks metode dan tidak harus mengulang tipe self di tanda tangan setiap metode, adalah untuk organisasi. Kami telah menaruh semua hal yang bisa kami lakukan dengan instance sebuah tipe di satu blok impl alih-alih membuat pengguna masa depan kode kami mencari kemampuan Rectangle di berbagai tempat di pustaka yang kami sediakan.

Perhatikan bahwa kami bisa memilih untuk memberi nama metode yang sama dengan salah satu bidang struct. Misalnya, kami bisa mendefinisikan metode pada Rectangle yang juga bernama width:

Di sini, kami memilih untuk membuat metode width mengembalikan true jika nilai di bidang width instance lebih besar dari 0 dan false jika nilainya 0: Kami bisa menggunakan bidang dalam metode dengan nama yang sama untuk tujuan apa pun. Di main, saat kami mengikuti rect1.width dengan tanda kurung, Rust tahu kami bermaksud metode width. Saat kami tidak menggunakan tanda kurung, Rust tahu kami bermaksud bidang width.

Sering, tapi tidak selalu, saat kami memberi nama metode yang sama dengan bidang kami ingin ia hanya mengembalikan nilai di bidang dan tidak melakukan apa pun lagi. Metode seperti ini disebut getters, dan Rust tidak mengimplementasikannya secara otomatis untuk bidang struct seperti beberapa bahasa lain. Getter berguna karena Anda bisa membuat bidang private tapi metode public dan dengan demikian mengaktifkan akses read-only ke bidang itu sebagai bagian dari API publik tipe. Kami akan membahas apa itu public dan private serta cara menunjuk bidang atau metode sebagai public atau private di Bab 7.

Di Mana Operator ->?

Di C dan C++, dua operator berbeda digunakan untuk memanggil metode: Anda menggunakan . jika memanggil metode pada objek langsung dan -> jika Anda memanggil metode pada pointer ke objek dan perlu dereferensikan pointer terlebih dahulu. Dengan kata lain, jika object adalah pointer, object->something() mirip dengan (*object).something().

Rust tidak memiliki ekuivalen untuk operator ->; sebagai gantinya, Rust memiliki fitur yang disebut automatic referencing and dereferencing. Memanggil metode adalah salah satu tempat sedikit di Rust dengan perilaku ini.

Begini caranya: Saat Anda memanggil metode dengan object.something(), Rust secara otomatis menambahkan &, &mut, atau * sehingga object cocok dengan tanda tangan metode. Dengan kata lain, hal berikut adalah sama:

#![allow(unused)]
fn main() {
#[derive(Debug,Copy,Clone)]
struct Point {
    x: f64,
    y: f64,
}

impl Point {
   fn distance(&self, other: &Point) -> f64 {
       let x_squared = f64::powi(other.x - self.x, 2);
       let y_squared = f64::powi(other.y - self.y, 2);

       f64::sqrt(x_squared + y_squared)
   }
}
let p1 = Point { x: 0.0, y: 0.0 };
let p2 = Point { x: 5.0, y: 6.5 };
p1.distance(&p2);
(&p1).distance(&p2);
}

Yang pertama terlihat jauh lebih bersih. Perilaku referensi otomatis ini berfungsi karena metode memiliki receiver yang jelas—tipe self. Diberikan receiver dan nama metode, Rust bisa secara definitif mengetahui apakah metode membaca (&self), memutasi (&mut self), atau mengonsumsi (self). Fakta bahwa Rust membuat peminjaman implisit untuk receiver metode adalah bagian besar dari membuat kepemilikan ergonomis dalam praktik.

Fungsi Terkait (Associated Functions)

Semua fungsi yang didefinisikan di dalam blok impl disebut fungsi terkait (associated functions) karena mereka terkait dengan tipe yang dinamai setelah impl. Kami bisa mendefinisikan fungsi terkait yang tidak memiliki self sebagai parameter pertama (dan dengan demikian bukan metode) karena mereka tidak butuh instance tipe untuk bekerja. Kami sudah menggunakan fungsi seperti ini: fungsi String::from yang didefinisikan pada tipe String.

Fungsi terkait yang bukan metode sering digunakan untuk konstruktor yang akan mengembalikan instance baru struct. Sering disebut new, tapi new bukan nama khusus dan tidak built-in ke bahasa. Misalnya, kami bisa memilih untuk menyediakan fungsi terkait bernama square yang akan memiliki satu parameter dimensi dan menggunakan itu sebagai lebar dan tinggi keduanya, sehingga memudahkan membuat Rectangle persegi alih-alih harus menentukan nilai yang sama dua kali:

Nama Berkas: src/main.rs

#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn square(size: u32) -> Self {
        Self {
            width: size,
            height: size,
        }
    }
}

fn main() {
    let sq = Rectangle::square(3);
}

Kata kunci Self di tipe kembali dan di badan fungsi adalah alias untuk tipe yang muncul setelah kata kunci impl, yang dalam kasus ini adalah Rectangle.

Untuk memanggil fungsi terkait ini, kami menggunakan sintaks :: dengan nama struct; let sq = Rectangle::square(3); adalah contoh. Fungsi ini dinamespace oleh struct: Sintaks :: digunakan untuk baik fungsi terkait dan namespace yang dibuat oleh modul. Kami akan membahas modul di Bab 7.

Ringkasan

Struct memungkinkan Anda membuat tipe kustom yang bermakna untuk domain Anda. Dengan menggunakan struct, Anda bisa menyimpan potongan data terkait tetap terhubung satu sama lain dan menamai setiap potongan untuk membuat kode Anda jelas. Di blok impl, Anda bisa mendefinisikan fungsi yang terkait dengan tipe Anda, dan metode adalah jenis fungsi terkait yang memungkinkan Anda menentukan perilaku yang dimiliki instance struct Anda.

Tapi struct bukan satu-satunya cara Anda bisa membuat tipe kustom: Mari beralih ke fitur enum Rust untuk menambahkan alat lain ke kotak alat Anda.
