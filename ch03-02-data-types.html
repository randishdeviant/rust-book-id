The Rust Programming Language

Tipe Data

Setiap nilai di Rust memiliki tipe data tertentu, yang memberitahu Rust jenis data apa yang ditentukan sehingga Rust tahu cara bekerja dengan data itu. Kami akan melihat dua subset tipe data: skalar dan majemuk.

Ingat bahwa Rust adalah bahasa statically typed (bertipe statis), yang berarti ia harus mengetahui tipe semua variabel pada waktu kompilasi. Compiler biasanya bisa menyimpulkan tipe apa yang ingin kita gunakan berdasarkan nilai dan cara kita menggunakannya. Dalam kasus di mana banyak tipe memungkinkan, seperti saat kami mengubah String ke tipe numerik menggunakan parse di bagian “Membandingkan Tebakan dengan Angka Rahasia” di Bab 2, kami harus menambahkan anotasi tipe, seperti ini:

#![allow(unused)]
fn main() {
let guess: u32 = "42".parse().expect("Not a number!");
}

Jika kami tidak menambahkan anotasi tipe : u32 seperti yang ditunjukkan di kode sebelumnya, Rust akan menampilkan kesalahan berikut, yang berarti compiler membutuhkan lebih banyak informasi dari kami untuk mengetahui tipe apa yang kami inginkan:

Tipe Skalar

Tipe skalar merepresentasikan nilai tunggal. Rust memiliki empat tipe skalar utama: integer, floating-point (bilangan pecahan), Boolean, dan karakter. Anda mungkin mengenal ini dari bahasa pemrograman lain. Mari langsung ke cara kerjanya di Rust.

Tipe Integer

Sebuah integer adalah angka tanpa komponen pecahan. Kami menggunakan satu tipe integer di Bab 2, tipe u32. Deklarasi tipe ini menunjukkan bahwa nilai yang terkait dengannya seharusnya adalah integer tanpa tanda (tipe integer bertanda dimulai dengan i bukan u) yang memakan 32 bit ruang. Tabel 3-1 menunjukkan tipe integer built-in di Rust. Kita bisa menggunakan varian apa pun dari ini untuk mendeklarasikan tipe nilai integer.

Tabel 3-1: Tipe Integer di Rust

Setiap varian bisa bertanda atau tanpa tanda dan memiliki ukuran eksplisit. Bertanda (signed) dan tanpa tanda (unsigned) mengacu pada apakah mungkin bagi angka untuk negatif—dengan kata lain, apakah angka perlu memiliki tanda bersamanya (bertanda) atau apakah ia hanya akan pernah positif dan oleh karena itu bisa direpresentasikan tanpa tanda (tanpa tanda). Ini seperti menulis angka di kertas: Ketika tanda penting, angka ditampilkan dengan tanda plus atau minus; namun, jika aman mengasumsikan angka positif, ditampilkan tanpa tanda. Angka bertanda disimpan menggunakan representasi two’s complement.

Setiap varian bertanda bisa menyimpan angka dari −(2n − 1) sampai 2n − 1 − 1 inklusif, di mana n adalah jumlah bit yang digunakan varian tersebut. Jadi, i8 bisa menyimpan angka dari −(27) sampai 27 − 1, yang sama dengan −128 sampai 127. Varian tanpa tanda bisa menyimpan angka dari 0 sampai 2n − 1, jadi u8 bisa menyimpan angka dari 0 sampai 28 − 1, yang sama dengan 0 sampai 255.

Selain itu, tipe isize dan usize bergantung pada arsitektur komputer tempat program Anda berjalan: 64 bit jika Anda di arsitektur 64-bit dan 32 bit jika Anda di arsitektur 32-bit.

Anda bisa menulis literal integer dalam bentuk apa pun yang ditampilkan di Tabel 3-2. Perhatikan bahwa literal angka yang bisa menjadi beberapa tipe numerik mengizinkan sufiks tipe, seperti 57u8, untuk menunjuk tipe. Literal angka juga bisa menggunakan _ sebagai pemisah visual untuk memudahkan pembacaan angka, seperti 1_000, yang akan memiliki nilai yang sama seperti jika Anda menentukan 1000.

Jadi bagaimana Anda tahu tipe integer mana yang harus digunakan? Jika Anda tidak yakin, default Rust umumnya tempat yang baik untuk memulai: Tipe integer default ke i32. Situasi utama di mana Anda akan menggunakan isize atau usize adalah saat mengindeks beberapa jenis koleksi.

Overflow Integer

Katakanlah Anda memiliki variabel bertipe u8 yang bisa menampung nilai antara 0 dan 255. Jika Anda mencoba mengubah variabel ke nilai di luar rentang tersebut, seperti 256, integer overflow akan terjadi, yang bisa menghasilkan salah satu dari dua perilaku. Saat Anda mengompilasi dalam mode debug, Rust menyertakan pemeriksaan overflow integer yang menyebabkan program Anda panic di runtime jika perilaku ini terjadi. Rust menggunakan istilah panicking ketika program keluar dengan kesalahan; kami akan membahas panic lebih mendalam di bagian “Kesalahan Tak Terpulihkan dengan panic!”<!–

ignore –> di Bab 9.

Saat Anda mengompilasi dalam mode release dengan flag --release, Rust tidak menyertakan pemeriksaan overflow integer yang menyebabkan panic. Sebagai gantinya, jika overflow terjadi, Rust melakukan two’s complement wrapping. Singkatnya, nilai yang lebih besar dari nilai maksimum yang bisa ditampung tipe “melintasi” (wrap around) ke minimum nilai yang bisa ditampung tipe tersebut. Dalam kasus u8, nilai 256 menjadi 0, nilai 257 menjadi 1, dan seterusnya. Program tidak akan panic, tapi variabel akan memiliki nilai yang mungkin bukan apa yang Anda harapkan. Mengandalkan perilaku wrapping overflow integer dianggap sebagai kesalahan.

Untuk secara eksplisit menangani kemungkinan overflow, Anda bisa menggunakan keluarga metode ini yang disediakan oleh pustaka standar untuk tipe numerik primitif:

  • Wrap di semua mode kompilasi dengan metode wrapping_*, seperti wrapping_add.
  • Mengembalikan nilai None jika ada overflow dengan metode checked_*.
  • Mengembalikan nilai dan Boolean yang menunjukkan apakah ada overflow dengan metode overflowing_*.
  • Saturasi di nilai minimum atau maksimum nilai dengan metode saturating_*.

Tipe Floating-Point

Rust juga memiliki dua tipe primitif untuk bilangan floating-point, yaitu angka dengan titik desimal. Tipe floating-point Rust adalah f32 dan f64, yang berukuran 32 bit dan 64 bit, masing-masing. Tipe default adalah f64 karena pada CPU modern, kecepatannya kira-kira sama dengan f32 tapi mampu presisi lebih tinggi. Semua tipe floating-point bertanda.

Berikut contoh yang menunjukkan bilangan floating-point dalam aksi:

Nama Berkas: src/main.rs

fn main() {
    let x = 2.0; // f64

    let y: f32 = 3.0; // f32
}

Bilangan floating-point direpresentasikan sesuai standar IEEE-754.

Operasi Numerik

Rust mendukung operasi matematika dasar yang Anda harapkan untuk semua tipe angka: penjumlahan, pengurangan, perkalian, pembagian, dan sisa bagi (remainder). Pembagian integer memotong (truncates) menuju nol ke integer terdekat. Kode berikut menunjukkan bagaimana Anda akan menggunakan setiap operasi numerik dalam pernyataan let:

Nama Berkas: src/main.rs

fn main() {
    // addition
    let sum = 5 + 10;

    // subtraction
    let difference = 95.5 - 4.3;

    // multiplication
    let product = 4 * 30;

    // division
    let quotient = 56.7 / 32.2;
    let truncated = -5 / 3; // Results in -1

    // remainder
    let remainder = 43 % 5;
}

Setiap ekspresi dalam pernyataan ini menggunakan operator matematika dan mengevaluasi ke nilai tunggal, yang kemudian terikat ke variabel. Lampiran B berisi daftar semua operator yang disediakan Rust.

Tipe Boolean

Seperti di kebanyakan bahasa pemrograman lain, tipe Boolean di Rust memiliki dua nilai mungkin: true dan false. Boolean berukuran satu byte. Tipe Boolean di Rust ditentukan menggunakan bool. Misalnya:

Nama Berkas: src/main.rs

fn main() {
    let t = true;

    let f: bool = false; // with explicit type annotation
}

Cara utama menggunakan nilai Boolean adalah melalui kondisional, seperti ekspresi if. Kami akan membahas cara kerja ekspresi if di Rust di bagian “Alur Kontrol”.

Tipe Karakter

Tipe char Rust adalah tipe alfabetik paling primitif bahasa ini. Berikut beberapa contoh mendeklarasikan nilai char:

Nama Berkas: src/main.rs

fn main() {
    let c = 'z';
    let z: char = 'ℤ'; // with explicit type annotation
    let heart_eyed_cat = '😻';
}

Perhatikan bahwa kami menentukan literal char dengan tanda kutip tunggal, berlawanan dengan literal string, yang menggunakan tanda kutip ganda. Tipe char Rust berukuran 4 byte dan mewakili nilai skalar Unicode, yang berarti ia bisa mewakili jauh lebih banyak dari hanya ASCII. Huruf beraksen; karakter Cina, Jepang, dan Korea; emoji; dan spasi nol-lebar semuanya adalah nilai char yang valid di Rust. Nilai skalar Unicode berkisar dari U+0000 ke U+D7FF dan U+E000 ke U+10FFFF inklusif. Akan tetapi, “karakter” bukan benar-benar konsep di Unicode, jadi intuisi manusia Anda tentang apa itu “karakter” mungkin tidak cocok dengan char di Rust. Kami akan membahas topik ini detail di “Menyimpan Teks UTF-8 dengan String” di Bab 8.

Tipe Majemuk

Tipe majemuk (compound types) bisa mengelompokkan beberapa nilai ke dalam satu tipe. Rust memiliki dua tipe majemuk primitif: tuple dan array.

Tipe Tuple

Sebuah tuple adalah cara umum mengelompokkan sejumlah nilai dengan berbagai tipe ke dalam satu tipe majemuk. Tuple memiliki panjang tetap: Setelah dideklarasikan, mereka tidak bisa berkembang atau menyusut dalam ukuran.

Kami membuat tuple dengan menulis daftar nilai yang dipisahkan koma di dalam tanda kurung. Setiap posisi di tuple memiliki tipe, dan tipe nilai-nilai berbeda di tuple tidak harus sama. Kami menambahkan anotasi tipe opsional di contoh ini:

Nama Berkas: src/main.rs

fn main() {
    let tup: (i32, f64, u8) = (500, 6.4, 1);
}

Variabel tup terikat ke seluruh tuple karena tuple dianggap satu elemen majemuk tunggal. Untuk mendapatkan nilai-nilai individual dari tuple, kita bisa menggunakan pencocokan pola untuk mendestrukturisasi nilai tuple, seperti ini:

Nama Berkas: src/main.rs

fn main() {
    let tup = (500, 6.4, 1);

    let (x, y, z) = tup;

    println!("The value of y is: {y}");
}

Program ini pertama kali membuat tuple dan mengikatnya ke variabel tup. Lalu ia menggunakan pola dengan let untuk mengambil tup dan mengubahnya menjadi tiga variabel terpisah, x, y, dan z. Ini disebut destructuring karena ia memecah satu tuple menjadi tiga bagian. Akhirnya, program mencetak nilai y, yaitu 6.4.

Kita juga bisa mengakses elemen tuple langsung dengan menggunakan titik (.) diikuti oleh indeks nilai yang ingin kita akses. Misalnya:

Nama Berkas: src/main.rs

fn main() {
    let x: (i32, f64, u8) = (500, 6.4, 1);

    let five_hundred = x.0;

    let six_point_four = x.1;

    let one = x.2;
}

Program ini membuat tuple x dan kemudian mengakses setiap elemen tuple menggunakan indeks masing-masing. Seperti kebanyakan bahasa pemrograman, indeks pertama di tuple adalah 0.

Tuple tanpa nilai apa pun memiliki nama khusus, unit. Nilai ini dan tipe yang sesuai keduanya ditulis () dan mewakili nilai kosong atau tipe pengembalian kosong. Ekspresi secara implisit mengembalikan nilai unit jika mereka tidak mengembalikan nilai lain.

Tipe Array

Cara lain untuk memiliki koleksi beberapa nilai adalah dengan array. Berbeda dengan tuple, setiap elemen array harus memiliki tipe yang sama. Berbeda dengan array di beberapa bahasa lain, array di Rust memiliki panjang tetap.

Kami menulis nilai-nilai dalam array sebagai daftar yang dipisahkan koma di dalam tanda kurung siku:

Nama Berkas: src/main.rs

fn main() {
    let a = [1, 2, 3, 4, 5];
}

Array berguna saat Anda ingin data Anda dialokasikan di stack, sama seperti tipe lain yang telah kami lihat sejauh ini, bukannya di heap (kami akan membahas stack dan heap lebih lanjut di Bab 4) atau saat Anda ingin memastikan bahwa Anda selalu memiliki jumlah elemen yang tetap. Array tidak sefleksibel tipe vector, meskipun. Vector adalah tipe koleksi serupa yang disediakan pustaka standar yang diizinkan berkembang atau menyusut dalam ukuran karena isinya hidup di heap. Jika Anda ragu apakah menggunakan array atau vector, kemungkinan besar Anda seharusnya menggunakan vector. Bab 8 membahas vector lebih detail.

Namun, array lebih berguna saat Anda tahu jumlah elemen tidak akan perlu berubah. Misalnya, jika Anda menggunakan nama-nama bulan dalam program, Anda mungkin akan menggunakan array bukannya vector karena Anda tahu itu akan selalu berisi 12 elemen:

#![allow(unused)]
fn main() {
let months = ["Januari", "Februari", "Maret", "April", "Mei", "Juni", "Juli",
              "Agustus", "September", "Oktober", "November", "Desember"];
}

Anda menulis tipe array menggunakan tanda kurung siku dengan tipe setiap elemen, titik koma, dan kemudian jumlah elemen dalam array, seperti ini:

#![allow(unused)]
fn main() {
let a: [i32; 5] = [1, 2, 3, 4, 5];
}

Di sini, i32 adalah tipe setiap elemen. Setelah titik koma, angka 5 menunjukkan array berisi lima elemen.

Anda juga bisa menginisialisasi array untuk berisi nilai yang sama untuk setiap elemen dengan menentukan nilai awal, diikuti titik koma, dan kemudian panjang array dalam tanda kurung siku, seperti yang ditunjukkan di sini:

#![allow(unused)]
fn main() {
let a = [3; 5];
}

Array bernama a akan berisi 5 elemen yang semuanya diatur ke nilai 3 awalnya. Ini sama dengan menulis let a = [3, 3, 3, 3, 3]; tapi dengan cara yang lebih ringkas.

Akses Elemen Array

Array adalah sepotong memori tunggal dengan ukuran tetap yang diketahui yang bisa dialokasikan di stack. Anda bisa mengakses elemen array menggunakan indeksing, seperti ini:

Nama Berkas: src/main.rs

fn main() {
    let a = [1, 2, 3, 4, 5];

    let first = a[0];
    let second = a[1];
}

Dalam contoh ini, variabel bernama first akan mendapatkan nilai 1 karena itu adalah nilai pada indeks [0] di array. Variabel bernama second akan mendapatkan nilai 2 dari indeks [1] di array.

Akses Elemen Array Tidak Valid

Mari lihat apa yang terjadi jika Anda mencoba mengakses elemen array yang melewati akhir array. Katakanlah Anda menjalankan kode ini, mirip dengan permainan tebak angka di Bab 2, untuk mendapatkan indeks array dari pengguna:

Nama Berkas: src/main.rs

use std::io;

fn main() {
    let a = [1, 2, 3, 4, 5];

    println!("Please enter an array index.");

    let mut index = String::new();

    io::stdin()
        .read_line(&mut index)
        .expect("Failed to read line");

    let index: usize = index
        .trim()
        .parse()
        .expect("Index entered was not a number");

    let element = a[index];

    println!("The value of the element at index {index} is: {element}");
}

Kode ini kompilasi dengan sukses. Jika Anda menjalankan kode ini menggunakan cargo run dan memasukkan 0, 1, 2, 3, atau 4, program akan mencetak nilai yang sesuai pada indeks itu di array. Jika Anda malah memasukkan angka melewati akhir array, seperti 10, Anda akan melihat keluaran seperti ini:

thread 'main' panicked at src/main.rs:19:19:
index out of bounds: the len is 5 but the index is 10
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

Program menghasilkan kesalahan runtime pada saat menggunakan nilai tidak valid dalam operasi indeksing. Program keluar dengan pesan kesalahan dan tidak mengeksekusi pernyataan println! final. Saat Anda mencoba mengakses elemen menggunakan indeksing, Rust akan memeriksa apakah indeks yang Anda tentukan kurang dari panjang array. Jika indeks lebih besar dari atau sama dengan panjang, Rust akan panic. Pemeriksaan ini harus terjadi pada runtime, terutama dalam kasus ini, karena compiler tidak mungkin tahu nilai apa yang akan dimasukkan pengguna saat mereka menjalankan kode nanti.

Ini adalah contoh prinsip keamanan memori Rust dalam aksi. Di banyak bahasa tingkat rendah, jenis pemeriksaan ini tidak dilakukan, dan saat Anda memberikan indeks yang salah, memori tidak valid bisa diakses. Rust melindungi Anda dari jenis kesalahan ini dengan segera keluar alih-alih mengizinkan akses memori dan melanjutkan. Bab 9 membahas lebih lanjut penanganan kesalahan Rust dan bagaimana Anda bisa menulis kode yang aman, mudah dibaca, yang tidak panic dan tidak mengizinkan akses memori tidak valid.
