The Rust Programming Language

Tipe Slice

Slice memungkinkan Anda merujuk ke urutan berurutan elemen dalam sebuah koleksi. Slice adalah jenis referensi, jadi ia tidak memiliki kepemilikan.

Berikut masalah pemrograman kecil: Tulis fungsi yang mengambil string kata-kata yang dipisahkan spasi dan mengembalikan kata pertama yang ditemukan di string itu. Jika fungsi tidak menemukan spasi di string, seluruh string harus satu kata, jadi seluruh string harus dikembalikan.

Catatan: Untuk tujuan memperkenalkan slice, kami mengasumsikan hanya ASCII di bagian ini; pembahasan yang lebih menyeluruh tentang penanganan UTF-8 ada di bagian “Menyimpan Teks UTF-8 dengan String” Bab 8.

Mari kerjakan bagaimana kami akan menulis tanda tangan fungsi ini tanpa menggunakan slice, untuk memahami masalah yang akan diselesaikan slice:

fn first_word(s: &String) -> ?

Fungsi first_word memiliki parameter bertipe &String. Kami tidak butuh kepemilikan, jadi ini baik-baik saja. (Dalam Rust idiomatik, fungsi tidak mengambil kepemilikan argumen mereka kecuali mereka perlu, dan alasannya akan jelas seiring kami melanjutkan.) Tapi apa yang harus kami kembalikan? Kami tidak benar-benar punya cara untuk berbicara tentang bagian dari string. Namun, kami bisa mengembalikan indeks akhir kata, yang ditunjukkan oleh spasi. Mari coba itu, seperti yang ditunjukkan di Listing 4-7.

Karena kami perlu melalui String elemen per elemen dan memeriksa apakah nilai adalah spasi, kami akan mengubah String kami ke array byte menggunakan metode as_bytes.

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

fn main() {}

Selanjutnya, kami membuat iterator atas array byte menggunakan metode iter:

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

fn main() {}

Kami akan membahas iterator lebih detail di Bab 13. Untuk sekarang, ketahui bahwa iter adalah metode yang mengembalikan setiap elemen dalam koleksi dan enumerate membungkus hasil iter dan mengembalikan setiap elemen sebagai bagian dari tuple. Elemen pertama tuple yang dikembalikan dari enumerate adalah indeks, dan elemen kedua adalah referensi ke elemen. Ini agak lebih nyaman dari menghitung indeks sendiri.

Karena metode enumerate mengembalikan tuple, kami bisa menggunakan pola untuk mendestrukturisasi tuple itu. Kami akan membahas pola lebih lanjut di Bab 6. Di loop for, kami menentukan pola yang memiliki i untuk indeks di tuple dan &item untuk byte tunggal di tuple. Karena kami mendapat referensi ke elemen dari .iter().enumerate(), kami menggunakan & di pola.

Di dalam loop for, kami mencari byte yang mewakili spasi dengan menggunakan sintaks byte literal. Jika kami menemukan spasi, kami mengembalikan posisi. Sebaliknya, kami mengembalikan panjang string dengan menggunakan s.len().

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

fn main() {}

Kami sekarang punya cara untuk mengetahui indeks akhir kata pertama di string, tapi ada masalah. Kami mengembalikan usize sendiri, tapi itu hanya angka yang bermakna dalam konteks &String. Dengan kata lain, karena itu nilai terpisah dari String, tidak ada jaminan bahwa ia akan tetap valid di masa depan. Pertimbangkan program di Listing 4-8 yang menggunakan fungsi first_word dari Listing 4-7.

Program ini kompilasi tanpa kesalahan dan akan demikian juga jika kami menggunakan word setelah memanggil s.clear(). Karena word tidak terhubung ke keadaan s sama sekali, word tetap berisi nilai 5. Kami bisa menggunakan nilai 5 itu dengan variabel s untuk mencoba mengekstrak kata pertama keluar, tapi ini akan menjadi bug karena isi s telah berubah sejak kami menyimpan 5 di word.

Harus khawatir tentang indeks di word yang keluar dari sinkron dengan data di s itu merepotkan dan rentan kesalahan! Mengelola indeks ini bahkan lebih rapuh jika kami menulis fungsi second_word. Tanda tangannya harus terlihat seperti ini:

fn second_word(s: &String) -> (usize, usize) {

Sekarang kami melacak indeks awal dan akhir, dan kami punya lebih banyak nilai yang dihitung dari data dalam keadaan tertentu tapi tidak terikat ke keadaan itu sama sekali. Kami memiliki tiga variabel tidak terkait yang melayang yang perlu dijaga sinkron.

Untungnya, Rust punya solusi untuk masalah ini: string slice.

String Slice

Sebuah string slice adalah referensi ke urutan berurutan elemen dari String, dan terlihat seperti ini:

fn main() {
    let s = String::from("hello world");

    let hello = &s[0..5];
    let world = &s[6..11];
}

Alih-alih referensi ke seluruh String, hello adalah referensi ke bagian dari String, yang ditentukan di bit [0..5] tambahan. Kami membuat slice menggunakan range di dalam tanda kurung siku dengan menentukan [starting_index..ending_index], di mana starting_index adalah posisi pertama di slice dan ending_index adalah satu lebih dari posisi terakhir di slice. Secara internal, struktur data slice menyimpan posisi awal dan panjang slice, yang sesuai dengan ending_index dikurangi starting_index. Jadi, dalam kasus let world = &s[6..11];, world akan menjadi slice yang berisi pointer ke byte indeks 6 dari s dengan nilai panjang 5.

Gambar 4-7: String slice yang merujuk ke bagian String

Dengan sintaks range .. Rust, jika Anda ingin mulai di indeks 0, Anda bisa menghapus nilai sebelum dua titik. Dengan kata lain, ini sama:

#![allow(unused)]
fn main() {
let s = String::from("hello");

let slice = &s[0..2];
let slice = &s[..2];
}

Dengan token yang sama, jika slice Anda menyertakan byte terakhir dari String, Anda bisa menghapus angka di belakang. Artinya ini sama:

#![allow(unused)]
fn main() {
let s = String::from("hello");

let len = s.len();

let slice = &s[3..len];
let slice = &s[3..];
}

Anda juga bisa menghapus kedua nilai untuk mengambil slice dari seluruh string. Jadi, ini sama:

#![allow(unused)]
fn main() {
let s = String::from("hello");

let len = s.len();

let slice = &s[0..len];
let slice = &s[..];
}

Catatan: Indeks range string slice harus terjadi di batas karakter UTF-8 yang valid. Jika Anda mencoba membuat string slice di tengah karakter multibyte, program Anda akan keluar dengan kesalahan.

Mengembalikan slice juga akan berfungsi untuk fungsi second_word:

fn second_word(s: &String) -> &str {

Kami kini memiliki API yang langsung yang jauh lebih sulit untuk diacaukan karena compiler akan memastikan bahwa referensi ke String tetap valid. Ingat bug di program di Listing 4-8, saat kami mendapat indeks ke akhir kata pertama tapi lalu menghapus string sehingga indeks kami tidak valid? Kode itu secara logis tidak benar tapi tidak menunjukkan kesalahan langsung. Masalah akan muncul nanti jika kami terus mencoba menggunakan indeks kata pertama dengan string yang dikosongkan. Slice membuat bug ini tidak mungkin dan meminta kami jauh lebih awal bahwa kami punya masalah dengan kode kami. Menggunakan versi slice dari first_word akan melempar kesalahan waktu kompilasi:

Ingat dari aturan peminjaman bahwa jika kami memiliki referensi immutable ke sesuatu, kami tidak bisa juga mengambil referensi mutable. Karena clear perlu memotong String, ia perlu mendapatkan referensi mutable. println! setelah pemanggilan ke clear menggunakan referensi di word, jadi referensi immutable harus masih aktif pada titik itu. Rust melarang referensi mutable di clear dan referensi immutable di word ada pada waktu yang sama, dan kompilasi gagal. Tidak hanya Rust membuat API kami lebih mudah digunakan, tapi ia juga telah menghilangkan seluruh kelas kesalahan pada waktu kompilasi!

String Literal sebagai Slice

Ingat bahwa kami bicara tentang string literal disimpan di dalam binary. Sekarang kami tahu tentang slice, kami bisa dengan benar memahami string literal:

#![allow(unused)]
fn main() {
let s = "Hello, world!";
}

Tipe s di sini adalah &str: Ia adalah slice yang menunjuk ke titik spesifik tersebut dari binary. Inilah juga mengapa string literal tidak dapat diubah (immutable); &str adalah referensi immutable.

String Slice sebagai Parameter

Mengetahui bahwa Anda bisa mengambil slice dari literal dan nilai String mengarahkan kami ke satu peningkatan lagi pada first_word, dan itu adalah tanda tangannya:

fn first_word(s: &String) -> &str {

Rustacean yang lebih berpengalaman akan menulis tanda tangan yang ditampilkan di Listing 4-9 sebagai gantinya karena ia memungkinkan kami menggunakan fungsi yang sama pada nilai &String dan &str keduanya.

Jika kami memiliki string slice, kami bisa meneruskannya langsung. Jika kami memiliki String, kami bisa meneruskan slice dari String atau referensi ke String. Fleksibilitas ini memanfaatkan deref coercions, fitur yang akan kami bahas di bagian “Menggunakan Deref Coercions di Fungsi dan Metode” Bab 15.

Slice Lainnya

String slice, seperti yang mungkin Anda bayangkan, spesifik untuk string. Tapi ada tipe slice yang lebih umum juga. Pertimbangkan array ini:

#![allow(unused)]
fn main() {
let a = [1, 2, 3, 4, 5];
}

Sama seperti kami mungkin ingin merujuk ke bagian string, kami mungkin ingin merujuk ke bagian array. Kami akan melakukannya seperti ini:

#![allow(unused)]
fn main() {
let a = [1, 2, 3, 4, 5];

let slice = &a[1..3];

assert_eq!(slice, &[2, 3]);
}

Slice ini bertipe &[i32]. Ia bekerja cara yang sama seperti string slice, dengan menyimpan referensi ke elemen pertama dan panjang. Anda akan menggunakan jenis slice ini untuk semua macam koleksi lain. Kami akan membahas koleksi-koleksi ini detail saat kami membahas vector di Bab 8.

Ringkasan

Konsep kepemilikan, peminjaman, dan slice memastikan keamanan memori di program Rust pada waktu kompilasi. Bahasa Rust memberi Anda kontrol atas penggunaan memori Anda dengan cara yang sama seperti bahasa pemrograman sistem lain. Tapi dengan pemilik data yang secara otomatis membersihkan data itu saat pemilik keluar dari ruang lingkup berarti Anda tidak perlu menulis dan men-debug kode tambahan untuk mendapatkan kontrol ini.

Kepemilikan memengaruhi banyak bagian lain cara kerja Rust, jadi kami akan membahas konsep-konsep ini lebih lanjut sepanjang sisa buku. Mari lanjut ke Bab 5 dan lihat pengelompokan potongan data bersama-sama dalam struct.
