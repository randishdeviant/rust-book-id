The Rust Programming Language

Tipe Data Generik

Kami menggunakan generik untuk membuat definisi untuk item seperti tanda tangan fungsi atau struct, yang kemudian bisa kami gunakan dengan banyak tipe data konkret yang berbeda. Mari pertama lihat cara mendefinisikan fungsi, struct, enum, dan metode menggunakan generik. Lalu, kami akan membahas bagaimana generik memengaruhi performa kode.

Dalam Definisi Fungsi

Saat mendefinisikan fungsi yang menggunakan generik, kami meletakkan generik di tanda tangan fungsi di tempat biasanya kami menentukan tipe data parameter dan nilai kembalian. Melakukannya membuat kode kami lebih fleksibel dan memberikan fungsionalitas lebih banyak kepada pemanggil fungsi kami sambil mencegah duplikasi kode.

Melanjutkan dengan fungsi largest kami, Listing 10-4 menunjukkan dua fungsi yang keduanya menemukan nilai terbesar di slice. Kami kemudian akan menggabungkan ini menjadi satu fungsi yang menggunakan generik.

Fungsi largest_i32 adalah yang kami ekstrak di Listing 10-3 yang menemukan i32 terbesar di slice. Fungsi largest_char menemukan char terbesar di slice. Badan fungsi memiliki kode yang sama, jadi mari hapus duplikasi dengan memperkenalkan parameter tipe generik di satu fungsi.

Untuk memparameterisasi tipe di fungsi tunggal baru, kami perlu menamai parameter tipe, sama seperti yang kami lakukan untuk parameter nilai ke fungsi. Anda bisa menggunakan identifier apa pun sebagai nama parameter tipe. Tapi kami akan menggunakan T karena, berdasarkan konvensi, nama parameter tipe di Rust pendek, sering hanya satu huruf, dan konvensi penamaan tipe Rust adalah UpperCamelCase. Singkatan dari type, T adalah pilihan default kebanyakan programmer Rust.

Saat kami menggunakan parameter di badan fungsi, kami harus mendeklarasikan nama parameter di tanda tangan sehingga compiler tahu apa arti nama itu. Demikian pula, saat kami menggunakan nama parameter tipe di tanda tangan fungsi, kami harus mendeklarasikan nama parameter tipe sebelum menggunakannya. Untuk mendefinisikan fungsi generik largest, kami meletakkan deklarasi nama tipe di dalam tanda kurung sudut, <>, di antara nama fungsi dan daftar parameter, seperti ini:

fn largest<T>(list: &[T]) -> &T {

Kami membaca definisi ini sebagai “Fungsi largest bersifat generik atas suatu tipe T.” Fungsi ini memiliki satu parameter bernama list, yang adalah slice nilai bertipe T. Fungsi largest akan mengembalikan referensi ke nilai bertipe T yang sama.

Listing 10-5 menunjukkan definisi fungsi largest yang digabungkan menggunakan tipe data generik di tanda tangannya. Listing juga menunjukkan cara memanggil fungsi dengan slice nilai i32 atau char. Perhatikan bahwa kode ini belum akan kompilasi.

Teks bantuan menyebutkan std::cmp::PartialOrd, yang adalah trait, dan kami akan membahas trait di bagian selanjutnya. Untuk sekarang, ketahui bahwa kesalahan ini menyatakan bahwa badan largest tidak akan berfungsi untuk semua tipe mungkin yang T bisa jadi. Karena kami ingin membandingkan nilai bertipe T di badan, kami hanya bisa menggunakan tipe yang nilainya bisa diurutkan. Untuk mengaktifkan perbandingan, pustaka standar memiliki trait std::cmp::PartialOrd yang bisa Anda implementasikan pada tipe (lihat Lampiran C untuk lebih lanjut tentang trait ini). Untuk memperbaiki Listing 10-5, kami bisa mengikuti saran teks bantuan dan membatasi tipe yang valid untuk T hanya ke tipe-tipe yang mengimplementasikan PartialOrd. Listing akan lalu kompilasi, karena pustaka standar mengimplementasikan PartialOrd pada baik i32 maupun char.

Dalam Definisi Struct

Kami juga bisa mendefinisikan struct untuk menggunakan parameter tipe generik di satu atau lebih bidang menggunakan sintaks <>. Listing 10-6 mendefinisikan struct Point<T> untuk menampung nilai koordinat x dan y dari tipe apa pun.

Sintaks untuk menggunakan generik di definisi struct mirip dengan yang digunakan di definisi fungsi. Pertama, kami mendeklarasikan nama parameter tipe di dalam tanda kurung sudut tepat setelah nama struct. Lalu, kami menggunakan tipe generik di definisi struct di tempat kami sebaliknya akan menentukan tipe data konkret.

Perhatikan bahwa karena kami hanya menggunakan satu tipe generik untuk mendefinisikan Point<T>, definisi ini mengatakan bahwa struct Point<T> generik atas suatu tipe T, dan bidang x dan y keduanya tipe yang sama, apapun tipe itu. Jika kami membuat instance Point<T> yang memiliki nilai tipe berbeda, seperti di Listing 10-7, kode kami tidak akan kompilasi.

Dalam contoh ini, saat kami menetapkan nilai integer 5 ke x, kami memberitahu compiler bahwa tipe generik T akan menjadi integer untuk instance Point<T> ini. Lalu, saat kami menentukan 4.0 untuk y, yang kami definisikan memiliki tipe yang sama dengan x, kami akan mendapat kesalahan ketidakcocokan tipe seperti ini:

$ cargo run
   Compiling chapter10 v0.1.0 (file:///projects/chapter10)
error[E0308]: mismatched types
 --> src/main.rs:7:38
  |
7 |     let wont_work = Point { x: 5, y: 4.0 };
  |                                      ^^^ expected integer, found floating-point number

For more information about this error, try `rustc --explain E0308`.
error: could not compile `chapter10` (bin "chapter10") due to 1 previous error

Untuk mendefinisikan struct Point di mana x dan y keduanya generik tapi bisa memiliki tipe berbeda, kami bisa menggunakan beberapa parameter tipe generik. Misalnya, di Listing 10-8, kami mengubah definisi Point menjadi generik atas tipe T dan U di mana x bertipe T dan y bertipe U.

Sekarang semua instance Point yang ditampilkan diizinkan! Anda bisa menggunakan sebanyak parameter tipe generik di definisi yang Anda mau, tapi menggunakan lebih dari beberapa membuat kode Anda sulit dibaca. Jika Anda menemukan Anda butuh banyak tipe generik di kode Anda, bisa jadi kode Anda perlu restrukturisasi ke potongan yang lebih kecil.

Dalam Definisi Enum

Seperti yang kami lakukan dengan struct, kami bisa mendefinisikan enum untuk menampung tipe data generik di varian mereka. Mari lihat lagi enum Option<T> yang disediakan pustaka standar, yang kami gunakan di Bab 6:

#![allow(unused)]
fn main() {
enum Option<T> {
    Some(T),
    None,
}
}

Definisi ini seharusnya sekarang lebih masuk akal bagi Anda. Seperti yang Anda lihat, enum Option<T> generik atas tipe T dan memiliki dua varian: Some, yang menampung satu nilai bertipe T, dan varian None yang tidak menampung nilai apa pun. Dengan menggunakan enum Option<T>, kami bisa mengekspresikan konsep abstrak nilai opsional, dan karena Option<T> generik, kami bisa menggunakan abstraksi ini tidak peduli tipe apa nilai opsionalnya.

Enum bisa menggunakan beberapa tipe generik juga. Definisi enum Result yang kami gunakan di Bab 9 adalah salah satu contoh:

#![allow(unused)]
fn main() {
enum Result<T, E> {
    Ok(T),
    Err(E),
}
}

Enum Result generik atas dua tipe, T dan E, dan memiliki dua varian: Ok, yang menampung nilai bertipe T, dan Err, yang menampung nilai bertipe E. Definisi ini membuat nyaman penggunaan enum Result di mana pun kami memiliki operasi yang mungkin sukses (mengembalikan nilai bertipe T) atau gagal (mengembalikan kesalahan bertipe E). Faktanya, ini yang kami gunakan untuk membuka berkas di Listing 9-3, di mana T diisi dengan tipe std::fs::File saat berkas dibuka dengan sukses dan E diisi dengan tipe std::io::Error saat ada masalah membuka berkas.

Saat Anda mengenali situasi di kode Anda dengan definisi struct atau enum beberapa yang hanya berbeda di tipe nilai yang mereka tampung, Anda bisa menghindari duplikasi dengan menggunakan tipe generik sebagai gantinya.

Dalam Definisi Metode

Kami bisa mengimplementasikan metode pada struct dan enum (seperti yang kami lakukan di Bab 5) dan menggunakan tipe generik di definisi mereka juga. Listing 10-9 menunjukkan struct Point<T> yang kami definisikan di Listing 10-6 dengan metode bernama x yang diimplementasikan padanya.

Di sini, kami telah mendefinisikan metode bernama x pada Point<T> yang mengembalikan referensi ke data di bidang x.

Perhatikan bahwa kami harus mendeklarasikan T tepat setelah impl sehingga kami bisa menggunakan T untuk menentukan bahwa kami mengimplementasikan metode pada tipe Point<T>. Dengan mendeklarasikan T sebagai tipe generik setelah impl, Rust bisa mengidentifikasi bahwa tipe di tanda kurung sudut di Point adalah tipe generik bukannya tipe konkret. Kami bisa memilih nama berbeda untuk parameter generik ini dari parameter generik yang dideklarasikan di definisi struct, tapi menggunakan nama yang sama adalah konvensi. Jika Anda menulis metode di dalam impl yang mendeklarasikan tipe generik, metode itu akan didefinisikan pada instance tipe apa pun, tidak peduli tipe konkret apa yang akhirnya menggantikan tipe generik.

Kami juga bisa menentukan batasan pada tipe generik saat mendefinisikan metode pada tipe. Kami bisa, misalnya, mengimplementasikan metode hanya pada instance Point<f32> bukannya pada instance Point<T> dengan tipe generik apa pun. Di Listing 10-10, kami menggunakan tipe konkret f32, artinya kami tidak mendeklarasikan tipe apa pun setelah impl.

Kode ini berarti tipe Point<f32> akan memiliki metode distance_from_origin; instance lain dari Point<T> di mana T bukan tipe f32 tidak akan memiliki metode ini didefinisikan. Metode ini mengukur sejauh mana titik kami dari titik di koordinat (0.0, 0.0) dan menggunakan operasi matematika yang hanya tersedia untuk tipe floating-point.

Parameter tipe generik di definisi struct tidak selalu sama dengan yang Anda gunakan di tanda tangan metode struct yang sama. Listing 10-11 menggunakan tipe generik X1 dan Y1 untuk struct Point dan X2 dan Y2 untuk tanda tangan metode mixup untuk membuat contoh lebih jelas. Metode ini membuat instance Point baru dengan nilai x dari Point self (bertipe X1) dan nilai y dari Point yang diteruskan (bertipe Y2).

Di main, kami telah mendefinisikan Point yang memiliki i32 untuk x (dengan nilai 5) dan f64 untuk y (dengan nilai 10.4). Variabel p2 adalah struct Point yang memiliki string slice untuk x (dengan nilai "Hello") dan char untuk y (dengan nilai c). Memanggil mixup pada p1 dengan argumen p2 memberi kami p3, yang akan memiliki i32 untuk x karena x berasal dari p1. Variabel p3 akan memiliki char untuk y karena y berasal dari p2. Pemanggilan makro println! akan mencetak p3.x = 5, p3.y = c.

Tujuan contoh ini adalah mendemonstrasikan situasi di mana beberapa parameter generik dideklarasikan dengan impl dan beberapa dideklarasikan dengan definisi metode. Di sini, parameter generik X1 dan Y1 dideklarasikan setelah impl karena mereka pergi dengan definisi struct. Parameter generik X2 dan Y2 dideklarasikan setelah fn mixup karena mereka hanya relevan untuk metode.

Performa Kode Menggunakan Generik

Anda mungkin bertanya-tanya apakah ada biaya runtime saat menggunakan parameter tipe generik. Kabar baiknya adalah menggunakan tipe generik tidak akan membuat program Anda berjalan lebih lambat dari menggunakan tipe konkret.

Rust mencapai ini dengan melakukan monomorfisasi (monomorphization) kode yang menggunakan generik pada waktu kompilasi. Monomorfisasi adalah proses mengubah kode generik menjadi kode spesifik dengan mengisi tipe konkret yang digunakan saat dikompilasi. Dalam proses ini, compiler melakukan kebalikan dari langkah-langkah yang kami gunakan untuk membuat fungsi generik di Listing 10-5: Compiler melihat semua tempat di mana kode generik dipanggil dan menghasilkan kode untuk tipe konkret yang kode generik dipanggil dengannya.

Mari lihat cara kerja ini dengan menggunakan enum generik Option<T> pustaka standar:

#![allow(unused)]
fn main() {
let integer = Some(5);
let float = Some(5.0);
}

Saat Rust mengompilasi kode ini, ia melakukan monomorfisasi. Selama proses itu, compiler membaca nilai yang telah digunakan di instance Option<T> dan mengidentifikasi dua jenis Option<T>: Satu adalah i32 dan yang lain f64. Sebagai bentuknya, ia memperluas definisi generik Option<T> menjadi dua definisi yang dikhususkan untuk i32 dan f64, dengan demikian menggantikan definisi generik dengan yang spesifik.

Versi yang dimonomorfisasi dari kode terlihat mirip dengan berikut (compiler menggunakan nama berbeda dari yang kami gunakan di sini untuk ilustrasi):

Generik Option<T> digantikan dengan definisi spesifik yang dibuat oleh compiler. Karena Rust mengompilasi kode generik menjadi kode yang menentukan tipe di setiap instance, kami tidak membayar biaya runtime untuk menggunakan generik. Saat kode berjalan, ia melakukan persis seperti jika kami telah menduplikasi setiap definisi secara manual. Proses monomorfisasi membuat generik Rust sangat efisien pada runtime.
