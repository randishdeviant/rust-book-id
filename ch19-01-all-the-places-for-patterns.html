The Rust Programming Language

Semua Tempat Pola Bisa Digunakan

Pola muncul di sejumlah tempat di Rust, dan Anda telah menggunakannya banyak tanpa sadar! Bagian ini membahas semua tempat di mana pola valid.

Arm match

Seperti yang dibahas di Bab 6, kami menggunakan pola di arm-arm ekspresi match. Secara formal, ekspresi match didefinisikan sebagai kata kunci match, sebuah nilai untuk dicocokkan, dan satu atau lebih arm match yang terdiri dari sebuah pola dan ekspresi yang dijalankan jika nilai cocok dengan pola arm tersebut, seperti ini:

match VALUE {
    PATTERN => EXPRESSION,
    PATTERN => EXPRESSION,
    PATTERN => EXPRESSION,
}

Misalnya, ini ekspresi match dari Listing 6-5 yang mencocokkan nilai Option<i32> di variabel x:

match x {
    None => None,
    Some(i) => Some(i + 1),
}

Polanya di ekspresi match ini adalah None dan Some(i) di kiri masing-masing panah.

Satu persyaratan untuk ekspresi match adalah mereka harus exhaustive (menyeupuhkan semua kemungkinan) dalam arti bahwa semua kemungkinan untuk nilai di ekspresi match harus dihitung. Satu cara untuk memastikan Anda sudah menutupi setiap kemungkinan adalah memiliki pola catch-all untuk arm terakhir: Misalnya, nama variabel yang mencocokkan nilai apa pun tidak akan pernah gagal dan dengan demikian menutupi setiap kasus yang tersisa.

Pola khusus _ akan mencocokkan apa pun, tapi tidak pernah mengikat ke variabel, jadi sering digunakan di arm match terakhir. Pola _ berguna saat Anda ingin mengabaikan nilai apa pun yang tidak dispesifikasikan, misalnya. Kami akan membahas pola _ lebih detail di “Mengabaikan Nilai dalam Pola” nanti di bab ini.

Pernyataan let

Sebelum bab ini, kami hanya secara eksplisit membahas penggunaan pola dengan match dan if let, tapi sebenarnya, kami telah menggunakan pola di tempat lain juga, termasuk di pernyataan let. Misalnya, pertimbangkan penetapan variabel sederhana ini dengan let:

#![allow(unused)]
fn main() {
let x = 5;
}

Setiap kali Anda menggunakan pernyataan let seperti ini Anda telah menggunakan pola, meski Anda mungkin tidak menyadarinya! Lebih formal, pernyataan let terlihat seperti ini:

let PATTERN = EXPRESSION;

Di pernyataan seperti let x = 5; dengan nama variabel di slot PATTERN, nama variabel hanyalah bentuk pola yang sangat sederhana. Rust membandingkan ekspresi dengan pola dan menetapkan nama apa pun yang ia temukan. Jadi, di contoh let x = 5;, x adalah pola yang berarti “ikat yang cocok di sini ke variabel x.” Karena nama x adalah keseluruhan pola, pola ini efektif berarti “ikat semuanya ke variabel x, apa pun nilai-nya.”

Untuk melihat aspek pencocokan pola dari let lebih jelas, pertimbangkan Listing 19-1, yang menggunakan pola dengan let untuk mendestrukturisasi tuple.

Di sini, kami mencocokkan tuple terhadap pola. Rust membandingkan nilai (1, 2, 3) dengan pola (x, y, z) dan melihat bahwa nilai cocok dengan pola—yaitu, ia melihat bahwa jumlah elemen sama di keduanya—jadi Rust mengikat 1 ke x, 2 ke y, dan 3 ke z. Anda bisa memikirkan pola tuple ini sebagai menyingkat tiga pola variabel individual di dalamnya.

Jika jumlah elemen di pola tidak cocok dengan jumlah elemen di tuple, tipe keseluruhan tidak akan cocok dan kami akan mendapat error compiler. Misalnya, Listing 19-2 menunjukkan upaya mendestrukturisasi tuple dengan tiga elemen ke dalam dua variabel, yang tidak akan berhasil.

Upaya mengompilasi kode ini menghasilkan kesalahan tipe ini:

$ cargo run
   Compiling patterns v0.1.0 (file:///projects/patterns)
error[E0308]: mismatched types
 --> src/main.rs:2:9
  |
2 |     let (x, y) = (1, 2, 3);
  |         ^^^^^^   --------- this expression has type `({integer}, {integer}, {integer})`
  |         |
  |         expected a tuple with 3 elements, found one with 2 elements
  |
  = note: expected tuple `({integer}, {integer}, {integer})`
             found tuple `(_, _)`

For more information about this error, try `rustc --explain E0308`.
error: could not compile `patterns` (bin "patterns") due to 1 previous error

Untuk memperbaiki error, kami bisa mengabaikan satu atau lebih nilai di tuple menggunakan _ atau .., seperti yang akan Anda lihat di bagian “Mengabaikan Nilai dalam Pola”. Jika masalahnya adalah kami punya terlalu banyak variabel di pola, solusinya adalah membuat tipe cocok dengan menghapus variabel sehingga jumlah variabel sama dengan jumlah elemen di tuple.

Ekspresi Kondisional if let

Di Bab 6, kami membahas cara menggunakan ekspresi if let utamanya sebagai cara lebih pendek untuk menulis yang setara dengan match yang hanya mencocokkan satu kasus. Secara opsional, if let bisa memiliki else yang berisi kode yang dijalankan jika pola di if let tidak cocok.

Listing 19-3 menunjukkan bahwa juga memungkinkan untuk mencampurkan ekspresi if let, else if, dan else if let. Melakukannya memberi kami fleksibilitas lebih dari ekspresi match di mana kami hanya bisa mengekspresikan satu nilai untuk dibandingkan dengan pola. Juga, Rust tidak mewajibkan kondisi dalam rangkaian arm if let, else if, dan else if let berkaitan satu sama lain.

Kode di Listing 19-3 menentukan warna apa yang akan dibuat background berdasarkan serangkaian pemeriksaan untuk beberapa kondisi. Untuk contoh ini, kami telah membuat variabel dengan nilai hardcoded yang program nyata mungkin terima dari input pengguna.

Jika pengguna menentukan warna favorit, warna itu digunakan sebagai background. Jika tidak ada warna favorit yang dispesifikasikan dan hari ini Selasa, warna background adalah hijau. Sebaliknya, jika pengguna menentukan usia mereka sebagai string dan kami bisa memparsnya sebagai angka dengan sukses, warnanya bisa ungu atau oranye tergantung nilai angkanya. Jika tidak ada kondisi ini yang terpenuhi, warna background adalah biru.

Struktur kondisional ini memungkinkan kami mendukung persyaratan kompleks. Dengan nilai hardcoded yang kami miliki di sini, contoh ini akan mencetak Using purple as the background color.

Anda bisa melihat bahwa if let juga bisa memperkenalkan variabel baru yang menyembunyikan (shadow) variabel existing dengan cara yang sama seperti arm match: Baris if let Ok(age) = age memperkenalkan variabel age baru yang berisi nilai di dalam varian Ok, menyembunyikan variabel age yang sudah ada. Artinya kami harus menempatkan kondisi if age > 30 di dalam blok itu: Kami tidak bisa menggabungkan dua kondisi ini ke if let Ok(age) = age && age > 30. Variabel age baru yang ingin kami bandingkan dengan 30 belum valid sampai scope baru dimulai dengan kurung kurawal.

Kelemahan menggunakan ekspresi if let adalah compiler tidak memeriksa exhaustiveness (kelengkapan), sedangkan dengan ekspresi match ia melakukannya. Jika kami menghilangkan blok else terakhir dan dengan demikian melewatkan penanganan beberapa kasus, compiler tidak akan memperingatkan kami tentang bug logika yang mungkin.

Loop Kondisional while let

Mirip konstruksi dengan if let, loop kondisional while let memungkinkan loop while berjalan selama pola terus cocok. Di Listing 19-4, kami menunjukkan loop while let yang menunggu pesan yang dikirim antar thread, tapi dalam kasus ini memeriksa Result alih-alih Option.

Contoh ini mencetak 1, 2, dan lalu 3. Metode recv mengambil pesan pertama dari sisi penerima channel dan mengembalikan Ok(value). Saat kami pertama kali melihat recv kembali di Bab 16, kami unwrap error secara langsung, atau kami berinteraksi dengannya sebagai iterator menggunakan loop for. Seperti yang ditunjukkan Listing 19-4, bagaimanapun, kami juga bisa menggunakan while let, karena metode recv mengembalikan Ok setiap kali pesan tiba, selama pengirim ada, dan kemudian menghasilkan Err sekali sisi pengirim terputus.

Loop for

Di loop for, nilai yang langsung mengikuti kata kunci for adalah sebuah pola. Misalnya, di for x in y, x adalah polanya. Listing 19-5 menunjukkan cara menggunakan pola di loop for untuk mendestrukturisasi, atau memecah, tuple sebagai bagian dari loop for.

Kode di Listing 19-5 akan mencetak berikut:

$ cargo run
   Compiling patterns v0.1.0 (file:///projects/patterns)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.52s
     Running `target/debug/patterns`
a is at index 0
b is at index 1
c is at index 2

Kami menyesuaikan iterator menggunakan metode enumerate sehingga ia menghasilkan nilai dan indeks untuk nilai itu, ditempatkan ke dalam tuple. Nilai pertama yang dihasilkan adalah tuple (0, 'a'). Saat nilai ini dicocokkan ke pola (index, value), index akan 0 dan value akan 'a', mencetak baris pertama output.

Parameter Fungsi

Parameter fungsi juga bisa berupa pola. Kode di Listing 19-6, yang mendeklarasikan fungsi bernama foo yang menerima satu parameter bernama x bertipe i32, seharusnya kini terlihat familiar.

Bagian x adalah pola! Seperti yang kami lakukan dengan let, kami bisa mencocokkan tuple di argumen fungsi ke pola. Listing 19-7 memecah nilai-nilai dalam tuple saat kami meneruskannya ke fungsi.

Kode ini mencetak Current location: (3, 5). Nilai &(3, 5) cocok dengan pola &(x, y), jadi x adalah nilai 3 dan y adalah nilai 5.

Kami juga bisa menggunakan pola di daftar parameter closure dengan cara yang sama seperti di daftar parameter fungsi karena closure mirip dengan fungsi, seperti yang dibahas di Bab 13.

Pada titik ini, Anda telah melihat beberapa cara menggunakan pola, tapi pola tidak bekerja sama di setiap tempat yang bisa kita gunakannya. Di beberapa tempat, pola harus irrefutable (tidak bisa ditolak); di keadaan lain, mereka bisa refutable (bisa ditolak). Kami akan membahas kedua konsep ini selanjutnya.
