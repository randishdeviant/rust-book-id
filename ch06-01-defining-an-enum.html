The Rust Programming Language

Mendefinisikan Enum

Di mana struct memberi Anda cara mengelompokkan bidang dan data terkait, seperti Rectangle dengan width dan height-nya, enum memberi Anda cara menyatakan bahwa sebuah nilai adalah salah satu dari sekumpulan nilai mungkin. Misalnya, kami mungkin ingin mengatakan bahwa Rectangle adalah salah satu dari sekumpulan bentuk mungkin yang juga menyertakan Circle dan Triangle. Untuk melakukannya, Rust memungkinkan kami mengodekan kemungkinan-kemungkinan ini sebagai enum.

Mari lihat situasi yang mungkin kami ingin ekspresikan dalam kode dan lihat mengapa enum berguna dan lebih tepat dari struct dalam kasus ini. Katakanlah kami perlu bekerja dengan alamat IP. Saat ini, dua standar utama digunakan untuk alamat IP: versi empat dan versi enam. Karena ini adalah satu-satunya kemungkinan untuk alamat IP yang akan dihadapi program kami, kami bisa enumerate (mendaftarkan) semua varian mungkin, itulah asal kata enumeration.

Alamat IP manapun bisa berupa versi empat atau versi enam, tapi tidak keduanya pada waktu yang sama. Properti alamat IP ini membuat struktur data enum tepat karena nilai enum hanya bisa menjadi salah satu variannya. Baik alamat versi empat maupun versi enam pada dasarnya tetap alamat IP, jadi mereka seharusnya diperlakukan sebagai tipe yang sama saat kode menangani situasi yang berlaku untuk jenis alamat IP manapun.

Kami bisa mengekspresikan konsep ini dalam kode dengan mendefinisikan enumerasi IpAddrKind dan mencantumkan jenis mungkin alamat IP, V4 dan V6. Ini adalah varian enum:

enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;

    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}

fn route(ip_kind: IpAddrKind) {}

IpAddrKind kini adalah tipe data kustom yang bisa kami gunakan di tempat lain di kode kami.

Nilai Enum

Kami bisa membuat instance dari masing-masing dua varian IpAddrKind seperti ini:

enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;

    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}

fn route(ip_kind: IpAddrKind) {}

Perhatikan bahwa varian enum di-namespace di bawah identifier-nya, dan kami menggunakan titik dua ganda untuk memisahkan keduanya. Ini berguna karena sekarang kedua nilai IpAddrKind::V4 dan IpAddrKind::V6 bertipe yang sama: IpAddrKind. Kami kemudian bisa, misalnya, mendefinisikan fungsi yang menerima IpAddrKind apa pun:

enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;

    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}

fn route(ip_kind: IpAddrKind) {}

Dan kami bisa memanggil fungsi ini dengan salah satu varian:

enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;

    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}

fn route(ip_kind: IpAddrKind) {}

Menggunakan enum bahkan memiliki keuntungan lebih. Berpikir lebih lanjut tentang tipe alamat IP kami, saat ini kami tidak punya cara menyimpan data alamat IP aktual; kami hanya tahu jenis apa itu. Mengikuti bahwa Anda baru belajar tentang struct di Bab 5, Anda mungkin tergoda untuk menangani masalah ini dengan struct seperti yang ditunjukkan di Listing 6-1.

Di sini, kami telah mendefinisikan struct IpAddr yang memiliki dua bidang: bidang kind yang bertipe IpAddrKind (enum yang kami definisikan sebelumnya) dan bidang address bertipe String. Kami memiliki dua instance struct ini. Yang pertama adalah home, dan ia memiliki nilai IpAddrKind::V4 sebagai kind-nya dengan data alamat terkait 127.0.0.1. Instance kedua adalah loopback. Ia memiliki varian lain dari IpAddrKind sebagai nilai kind-nya, V6, dan memiliki alamat ::1 yang terkait dengannya. Kami telah menggunakan struct untuk membungkus nilai kind dan address bersama-sama, jadi sekarang varian terkait dengan nilai itu.

Namun, mewakili konsep yang sama hanya dengan enum lebih ringkas: Alih-alih enum di dalam struct, kami bisa menaruh data langsung ke dalam setiap varian enum. Definisi baru ini dari enum IpAddr mengatakan bahwa baik varian V4 maupun V6 akan memiliki nilai String yang terkait:

fn main() {
    enum IpAddr {
        V4(String),
        V6(String),
    }

    let home = IpAddr::V4(String::from("127.0.0.1"));

    let loopback = IpAddr::V6(String::from("::1"));
}

Kami melampirkan data ke setiap varian enum secara langsung, sehingga tidak perlu struct tambahan. Di sini, juga lebih mudah melihat detail lain cara kerja enum: Nama setiap varian enum yang kami definisikan juga menjadi fungsi yang membangun instance enum. Artinya, IpAddr::V4() adalah pemanggilan fungsi yang menerima argumen String dan mengembalikan instance tipe IpAddr. Kami secara otomatis mendapatkan fungsi konstruktor ini didefinisikan sebagai hasil dari mendefinisikan enum.

Ada keuntungan lain menggunakan enum bukannya struct: Setiap varian bisa memiliki tipe dan jumlah data terkait yang berbeda. Alamat IP versi empat selalu akan memiliki empat komponen numerik yang akan memiliki nilai antara 0 dan 255. Jika kami ingin menyimpan alamat V4 sebagai empat nilai u8 tapi tetap mengekspresikan alamat V6 sebagai satu nilai String, kami tidak bisa melakukannya dengan struct. Enum menangani kasus ini dengan mudah:

fn main() {
    enum IpAddr {
        V4(u8, u8, u8, u8),
        V6(String),
    }

    let home = IpAddr::V4(127, 0, 0, 1);

    let loopback = IpAddr::V6(String::from("::1"));
}

Kami telah menunjukkan beberapa cara berbeda mendefinisikan struktur data untuk menyimpan alamat IP versi empat dan versi enam. Akan tetapi, seperti yang terjadi, keinginan menyimpan alamat IP dan mengodekan jenisnya sangat umum sehingga pustaka standar memiliki definisi yang bisa kami gunakan! Mari lihat bagaimana pustaka standar mendefinisikan IpAddr. Ia memiliki enum dan varian persis yang kami definisikan dan gunakan, tapi ia menanam data alamat di dalam varian dalam bentuk dua struct berbeda, yang didefinisikan berbeda untuk setiap varian:

#![allow(unused)]
fn main() {
struct Ipv4Addr {
    // --snip--
}

struct Ipv6Addr {
    // --snip--
}

enum IpAddr {
    V4(Ipv4Addr),
    V6(Ipv6Addr),
}
}

Kode ini menggambarkan bahwa Anda bisa menaruh jenis data apa pun di dalam varian enum: string, tipe numerik, atau struct, misalnya. Anda bahkan bisa menyertakan enum lain! Juga, tipe pustaka standar sering tidak jauh lebih kompleks dari yang mungkin Anda buat.

Perhatikan bahwa meskipun pustaka standar berisi definisi untuk IpAddr, kami masih bisa membuat dan menggunakan definisi sendiri kami tanpa konflik karena kami belum membawa definisi pustaka standar ke ruang lingkup kami. Kami akan membahas lebih lanjut tentang membawa tipe ke ruang lingkup di Bab 7.

Mari lihat contoh enum lain di Listing 6-2: Enum ini memiliki berbagai tipe yang tertanam di variannya.

Enum ini memiliki empat varian dengan tipe berbeda:

  • Quit: Tidak memiliki data yang terkait sama sekali
  • Move: Memiliki bidang bernama, seperti struct
  • Write: Menyertakan satu String
  • ChangeColor: Menyertakan tiga nilai i32

Mendefinisikan enum dengan varian seperti di Listing 6-2 mirip dengan mendefinisikan berbagai jenis definisi struct, kecuali enum tidak menggunakan kata kunci struct dan semua varian dikelompokkan bersama di bawah tipe Message. Struct-struct berikut bisa menampung data yang sama yang dipegang varian enum sebelumnya:

struct QuitMessage; // unit struct
struct MoveMessage {
    x: i32,
    y: i32,
}
struct WriteMessage(String); // tuple struct
struct ChangeColorMessage(i32, i32, i32); // tuple struct

fn main() {}

Tapi jika kami menggunakan struct yang berbeda, masing-masing memiliki tipe sendirinya, kami tidak akan bisa dengan mudah mendefinisikan fungsi untuk menerima salah satu jenis pesan ini seperti yang bisa kami lakukan dengan enum Message yang didefinisikan di Listing 6-2, yang merupakan tipe tunggal.

Ada satu kesamaan lagi antara enum dan struct: Sama seperti kami bisa mendefinisikan metode pada struct menggunakan impl, kami juga bisa mendefinisikan metode pada enum. Berikut metode bernama call yang bisa kami definisikan pada enum Message kami:

fn main() {
    enum Message {
        Quit,
        Move { x: i32, y: i32 },
        Write(String),
        ChangeColor(i32, i32, i32),
    }

    impl Message {
        fn call(&self) {
            // method body would be defined here
        }
    }

    let m = Message::Write(String::from("hello"));
    m.call();
}

Badan metode akan menggunakan self untuk mendapatkan nilai yang kami panggil metodenya. Dalam contoh ini, kami telah membuat variabel m yang bernilai Message::Write(String::from("hello")), dan itulah yang akan menjadi self di badan metode call saat m.call() dijalankan.

Mari lihat enum lain di pustaka standar yang sangat umum dan berguna: Option.

Enum Option

Bagian ini mengeksplorasi studi kasus Option, yang adalah enum lain yang didefinisikan oleh pustaka standar. Tipe Option mengodekan skenario sangat umum di mana sebuah nilai bisa berupa sesuatu, atau bisa tidak ada apa pun.

Misalnya, jika Anda meminta item pertama dalam daftar yang tidak kosong, Anda akan mendapat nilai. Jika Anda meminta item pertama dalam daftar kosong, Anda akan mendapat tidak ada apa pun. Mengekspresikan konsep ini dalam hal sistem tipe berarti compiler bisa memeriksa apakah Anda telah menangani semua kasus yang seharusnya Anda tangani; fungsionalitas ini bisa mencegah bug yang sangat umum di bahasa pemrograman lain.

Desain bahasa pemrograman sering dipikirkan dalam hal fitur apa yang disertakan, tapi fitur yang dikecualikan juga penting. Rust tidak memiliki fitur null yang banyak dimiliki bahasa lain. Null adalah nilai yang berarti tidak ada nilai di sana. Di bahasa dengan null, variabel selalu bisa berada dalam salah satu dari dua keadaan: null atau not-null.

Dalam presentasinya 2009 “Null References: The Billion Dollar Mistake,” Tony Hoare, penemu null, mengatakan ini:

Saya menyebutnya kesalahan miliar dolar saya. Saat itu, saya merancang sistem tipe komprehensif pertama untuk referensi di bahasa berorientasi objek. Tujuan saya adalah memastikan bahwa semua penggunaan referensi seharusnya benar-benar aman, dengan pemeriksaan yang dilakukan secara otomatis oleh compiler. Tapi saya tidak tahan godaan untuk memasukkan referensi null, hanya karena begitu mudah diimplementasikan. Ini telah mengarah pada kesalahan, kerentanan, dan crash sistem yang tak terhitung jumlahnya, yang mungkin telah menyebabkan kerugian dan kerusakan miliar dolar dalam empat puluh tahun terakhir.

Masalah dengan nilai null adalah jika Anda mencoba menggunakan nilai null sebagai nilai not-null, Anda akan mendapat kesalahan semacamnya. Karena properti null atau not-null ini meresap, sangat mudah membuat jenis kesalahan ini.

Akan tetapi, konsep yang null coba ekspresikan tetap berguna: Null adalah nilai yang saat ini tidak valid atau tidak ada untuk beberapa alasan.

Masalahnya bukan benar-benar pada konsep tapi pada implementasi khususnya. Sebagai akibatnya, Rust tidak memiliki null, tapi memiliki enum yang bisa mengodekan konsep nilai hadir atau tidak hadir. Enum ini adalah Option<T>, dan didefinisikan oleh pustaka standar sebagai berikut:

#![allow(unused)]
fn main() {
enum Option<T> {
    None,
    Some(T),
}
}

Enum Option<T> begitu berguna sehingga bahkan disertakan di prelude; Anda tidak perlu membawa ke ruang lingkup secara eksplisit. Varian-variannya juga disertakan di prelude: Anda bisa menggunakan Some dan None langsung tanpa awalan Option::. Enum Option<T> tetap hanya enum biasa, dan Some(T) dan None tetap varian bertipe Option<T>.

Sintaks <T> adalah fitur Rust yang belum kami bahas. Itu adalah parameter tipe generik, dan kami akan membahas generik lebih detail di Bab 10. Untuk sekarang, yang perlu Anda ketahui hanyalah <T> berarti varian Some dari enum Option bisa menampung satu potongan data dari tipe apa pun, dan setiap tipe konkret yang digunakan menggantikan T membuat tipe Option<T> secara keseluruhan menjadi tipe yang berbeda. Berikut beberapa contoh menggunakan nilai Option untuk menampung tipe angka dan karakter:

fn main() {
    let some_number = Some(5);
    let some_char = Some('e');

    let absent_number: Option<i32> = None;
}

Tipe some_number adalah Option<i32>. Tipe some_char adalah Option<char>, yang tipe berbeda. Rust bisa menyimpulkan tipe ini karena kami telah menentukan nilai di dalam varian Some. Untuk absent_number, Rust mewajibkan kami menganotasi tipe Option secara keseluruhan: Compiler tidak bisa menyimpulkan tipe yang akan dipegang varian Some yang sesuai hanya dengan melihat nilai None. Di sini, kami memberitahu Rust bahwa kami bermaksud absent_number bertipe Option<i32>.

Saat kami memiliki nilai Some, kami tahu bahwa nilai hadir, dan nilainya dipegang di dalam Some. Saat kami memiliki nilai None, dalam arti tertentu artinya hal yang sama dengan null: Kami tidak punya nilai yang valid. Jadi, mengapa memiliki Option<T> lebih baik dari memiliki null?

Singkatnya, karena Option<T> dan T (di mana T bisa tipe apa pun) adalah tipe yang berbeda, compiler tidak akan biarkan kami menggunakan nilai Option<T> seolah-olah itu pasti nilai yang valid. Misalnya, kode ini tidak akan kompilasi, karena mencoba menambahkan i8 ke Option<i8>:

fn main() {
    let x: i8 = 5;
    let y: Option<i8> = Some(5);

    let sum = x + y;
}

Intense! Secara efektif, pesan kesalahan ini berarti Rust tidak mengerti cara menambahkan i8 dan Option<i8>, karena mereka tipe berbeda. Saat kami memiliki nilai tipe seperti i8 di Rust, compiler akan memastikan kami selalu memiliki nilai yang valid. Kami bisa melanjutkan dengan percaya diri tanpa perlu memeriksa null sebelum menggunakan nilai itu. Hanya saat kami memiliki Option<i8> (atau tipe nilai apa pun yang kami kerjakan) kami harus khawatir tentang mungkin tidak memiliki nilai, dan compiler akan memastikan kami menangani kasus itu sebelum menggunakan nilai.

Dengan kata lain, Anda harus mengubah Option<T> ke T sebelum Anda bisa melakukan operasi T dengannya. Umumnya, ini membantu menangkap salah satu masalah paling umum dengan null: mengasumsikan sesuatu bukan null ketika sebenarnya null.

Menghilangkan risiko salah mengasumsikan nilai not-null membantu Anda lebih percaya diri dalam kode Anda. Untuk memiliki nilai yang mungkin null, Anda harus secara eksplisit opt-in dengan membuat tipe nilai itu Option<T>. Lalu, saat Anda menggunakan nilai itu, Anda diwajibkan secara eksplisit menangani kasus saat nilai itu null. Di mana pun nilai memiliki tipe yang bukan Option<T>, Anda bisa dengan aman mengasumsikan nilai itu bukan null. Ini adalah keputusan desain yang disengaja untuk Rust untuk membatasi pervasifnya null dan meningkatkan keamanan kode Rust.

Jadi bagaimana Anda mendapatkan nilai T keluar dari varian Some saat Anda memiliki nilai bertipe Option<T> agar Anda bisa menggunakan nilai itu? Enum Option<T> memiliki sejumlah besar metode yang berguna dalam berbagai situasi; Anda bisa memeriksanya di dokumentasinya. Menjadi akrab dengan metode di Option<T> akan sangat berguna dalam perjalanan Anda dengan Rust.

Secara umum, untuk menggunakan nilai Option<T>, Anda ingin memiliki kode yang akan menangani setiap varian. Anda ingin beberapa kode yang hanya akan berjalan saat Anda memiliki nilai Some(T), dan kode ini diizinkan menggunakan T di dalamnya. Anda ingin beberapa kode lain yang hanya berjalan jika Anda memiliki nilai None, dan kode itu tidak punya nilai T yang tersedia. Ekspresi match adalah konstruksi alur kontrol yang melakukan tepat ini saat digunakan dengan enum: Ia akan menjalankan kode berbeda tergantung pada varian enum mana yang dimilikinya, dan kode itu bisa menggunakan data di dalam nilai yang cocok.
