The Rust Programming Language

Memprogram Permainan Tebak Angka

Mari terjun ke Rust dengan mengerjakan proyek langsung bersama-sama! Bab ini memperkenalkan Anda pada beberapa konsep Rust umum dengan menunjukkan cara menggunakannya dalam program nyata. Anda akan belajar tentang let, match, metode, fungsi terkait (associated functions), crate eksternal, dan banyak lagi! Di bab-bab berikutnya, kami akan mengeksplorasi ide-ide ini lebih detail. Di bab ini, Anda hanya akan mempraktikkan dasar-dasarnya.

Kami akan mengimplementasikan masalah pemrograman pemula klasik: permainan tebak angka. Begini cara kerjanya: Program akan menghasilkan bilangan bulat acak antara 1 dan 100. Kemudian program akan meminta pemain memasukkan tebakan. Setelah tebakan dimasukkan, program akan menunjukkan apakah tebakan terlalu rendah atau terlalu tinggi. Jika tebakan benar, permainan akan mencetak pesan selamat dan keluar.

Menyiapkan Proyek Baru

Untuk menyiapkan proyek baru, buka direktori _projects_ yang Anda buat di Bab 1 dan buat proyek baru menggunakan Cargo, seperti ini:

$ cargo new guessing_game
$ cd guessing_game

Perintah pertama, cargo new, mengambil nama proyek (guessing_game) sebagai argumen pertama. Perintah kedua beralih ke direktori proyek baru.

Lihat berkas _Cargo.toml_ yang dihasilkan:

Nama Berkas: Cargo.toml

[package]
name = "guessing_game"
version = "0.1.0"
edition = "2024"

[dependencies]

Seperti yang Anda lihat di Bab 1, cargo new menghasilkan program “Halo, dunia!” untuk Anda. Periksa berkas _src/main.rs_:

Nama Berkas: src/main.rs

fn main() {
    println!("Hello, world!");
}

Sekarang mari kompilasi program “Halo, dunia!” ini dan jalankan dalam langkah yang sama menggunakan perintah cargo run:

$ cargo run
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.08s
     Running `target/debug/guessing_game`
Hello, world!

Perintah run berguna saat Anda perlu melakukan iterasi cepat pada proyek, seperti yang akan kami lakukan dalam game ini, dengan menguji setiap iterasi sebelum melanjutkan ke yang berikutnya.

Buka kembali berkas _src/main.rs_. Anda akan menulis semua kode di berkas ini.

Memproses Tebakan

Bagian pertama program permainan tebak angka akan meminta masukan pengguna, memproses masukan itu, dan memeriksa apakah masukan berada dalam bentuk yang diharapkan. Untuk memulai, kami akan mengizinkan pemain memasukkan tebakan. Masukkan kode di Listing 2-1 ke _src/main.rs_.

Kode ini mengandung banyak informasi, jadi mari tinjau baris per baris. Untuk mendapatkan masukan pengguna dan kemudian mencetak hasilnya sebagai keluaran, kami perlu memasukkan pustaka input/output io ke dalam ruang lingkup (scope). Pustaka io berasal dari pustaka standar, yang dikenal sebagai std:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

Secara default, Rust memiliki sekumpulan item yang didefinisikan di pustaka standar yang dibawa ke ruang lingkup setiap program. Kumpulan ini disebut prelude, dan Anda bisa melihat semuanya di dokumentasi pustaka standar.

Jika tipe yang ingin Anda gunakan tidak ada di prelude, Anda harus memasukkan tipe itu ke ruang lingkup secara eksplisit dengan pernyataan use. Menggunakan pustaka std::io menyediakan sejumlah fitur berguna, termasuk kemampuan menerima masukan pengguna.

Seperti yang Anda lihat di Bab 1, fungsi main adalah titik masuk ke program:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

Sintaks fn mendeklarasikan fungsi baru; tanda kurung, (), menunjukkan tidak ada parameter; dan tanda kurung kurawal, {, memulai badan fungsi.

Seperti yang Anda pelajari di Bab 1, println! adalah makro yang mencetak string ke layar:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

Kode ini mencetak prompt yang menyatakan permainan apa dan meminta masukan dari pengguna.

Menyimpan Nilai dengan Variabel

Selanjutnya, kami akan membuat sebuah variabel untuk menyimpan masukan pengguna, seperti ini:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

Sekarang program menjadi menarik! Banyak hal yang terjadi dalam baris kecil ini. Kami menggunakan pernyataan let untuk membuat variabel. Berikut contoh lain:

let apples = 5;

Baris ini membuat variabel baru bernama apples dan mengikatnya ke nilai 5. Di Rust, variabel secara default bersifat tidak dapat diubah (immutable), artinya setelah kita memberi variabel sebuah nilai, nilai itu tidak akan berubah. Kami akan membahas konsep ini secara detail di bagian “Variabel dan Ketidakberubahan” di Bab 3. Untuk membuat variabel dapat diubah (mutable), kita tambahkan mut sebelum nama variabel:

let apples = 5; // tidak dapat diubah
let mut bananas = 5; // dapat diubah

Catatan: Sintaks // memulai komentar yang berlanjut hingga akhir baris. Rust mengabaikan segala sesuatu di dalam komentar. Kami akan membahas komentar lebih detail di Bab 3.

Kembali ke program permainan tebak angka, Anda kini tahu bahwa let mut guess akan memperkenalkan variabel yang dapat diubah bernama guess. Tanda sama dengan (=) memberitahu Rust kita ingin mengikat sesuatu ke variabel sekarang. Di sebelah kanan tanda sama dengan adalah nilai yang guess ikat, yaitu hasil pemanggilan String::new, sebuah fungsi yang mengembalikan instance baru dari String. String adalah tipe string yang disediakan pustaka standar yang merupakan teks yang dapat berkembang, dikodekan UTF-8.

Sintaks :: di baris ::new menunjukkan bahwa new adalah fungsi terkait (associated function) dari tipe String. Fungsi terkait adalah fungsi yang diimplementasikan pada sebuah tipe, dalam hal ini String. Fungsi new ini membuat string baru, kosong. Anda akan menemukan fungsi new di banyak tipe karena ini nama umum untuk fungsi yang membuat nilai baru dari suatu jenis.

Secara lengkap, baris let mut guess = String::new(); telah membuat variabel yang dapat diubah yang saat ini terikat pada instance baru, kosong, dari String. Phew!

Menerima Masukan Pengguna

Ingat bahwa kami menyertakan fungsionalitas input/output dari pustaka standar dengan use std::io; di baris pertama program. Sekarang kami akan memanggil fungsi stdin dari modul io, yang akan memungkinkan kami menangani masukan pengguna:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

Jika kami tidak mengimpor modul io dengan use std::io; di awal program, kami masih bisa menggunakan fungsinya dengan menulis pemanggilan fungsi ini sebagai std::io::stdin. Fungsi stdin mengembalikan instance dari std::io::Stdin, yang merupakan tipe yang mewakili handle ke input standar untuk terminal Anda.

Selanjutnya, baris .read_line(&mut guess) memanggil metode read_line pada handle input standar untuk mendapatkan masukan dari pengguna. Kami juga meneruskan &mut guess sebagai argumen ke read_line untuk memberitahunya string apa untuk menyimpan masukan pengguna. Tugas penuh read_line adalah mengambil apa pun yang diketik pengguna ke input standar dan menambahkannya ke dalam string (tanpa menimpa isinya), sehingga kami oleh karena itu meneruskan string tersebut sebagai argumen. Argumen string perlu dapat diubah agar metode dapat mengubah isi string.

& menunjukkan bahwa argumen ini adalah referensi, yang memberi Anda cara untuk membiarkan beberapa bagian kode Anda mengakses satu potongan data tanpa perlu menyalin data itu ke memori beberapa kali. Referensi adalah fitur kompleks, dan salah satu keunggulan utama Rust adalah betapa aman dan mudahnya menggunakan referensi. Anda tidak perlu mengetahui banyak detail tersebut untuk menyelesaikan program ini. Untuk saat ini, yang perlu Anda ketahui hanyalah bahwa, seperti variabel, referensi secara default tidak dapat diubah (immutable). Oleh karena itu, Anda perlu menulis &mut guess bukan &guess untuk membuatnya dapat diubah. (Bab 4 akan menjelaskan referensi lebih menyeluruh.)

Menangani Potensi Kegagalan dengan Result

Kami masih bekerja pada baris kode ini. Kami sekarang membahas baris teks ketiga, tetapi perhatikan bahwa ini masih bagian dari satu baris kode logis tunggal. Bagian selanjutnya adalah metode ini:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

Kami bisa menulis kode ini sebagai:

io::stdin().read_line(&mut guess).expect("Failed to read line");

Namun, satu baris panjang sulit dibaca, jadi lebih baik membaginya. Sering kali bijaksana untuk memperkenalkan baris baru dan whitespace lain untuk membantu memecah baris panjang saat Anda memanggil metode dengan sintaks .method_name(). Sekarang mari bahas apa yang dilakukan baris ini.

Seperti yang disebutkan sebelumnya, read_line menaruh apa pun yang dimasukkan pengguna ke string yang kami teruskan kepadanya, tetapi ia juga mengembalikan nilai Result. Result adalah enumeration, sering disebut enum, yaitu tipe yang bisa berada di salah satu dari beberapa kemungkinan keadaan. Kami menyebut setiap kemungkinan keadaan sebagai varian.

Bab 6 akan membahas enum lebih detail. Tujuan tipe Result ini adalah untuk mengodekan informasi penanganan kesalahan.

Varian Result adalah Ok dan Err. Varian Ok menunjukkan operasi berhasil, dan berisi nilai yang berhasil dihasilkan. Varian Err berarti operasi gagal, dan berisi informasi tentang bagaimana atau mengapa operasi gagal.

Nilai tipe Result, seperti nilai tipe apa pun, memiliki metode yang didefinisikan padanya. Instance Result memiliki metode expect yang bisa Anda panggil. Jika instance Result ini bernilai Err, expect akan menyebabkan program berhenti (crash) dan menampilkan pesan yang Anda teruskan sebagai argumen ke expect. Jika metode read_line mengembalikan Err, kemungkinan besar itu hasil kesalahan yang berasal dari sistem operasi yang mendasari. Jika instance Result ini bernilai Ok, expect akan mengambil nilai kembali yang dipegang Ok dan mengembalikan hanya nilai itu kepada Anda supaya Anda bisa menggunakannya. Dalam hal ini, nilai tersebut adalah jumlah byte dalam masukan pengguna.

Jika Anda tidak memanggil expect, program akan kompilasi, tetapi Anda akan mendapat peringatan:

$ cargo build
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
warning: unused `Result` that must be used
  --> src/main.rs:10:5
   |
10 |     io::stdin().read_line(&mut guess);
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   |
   = note: this `Result` may be an `Err` variant, which should be handled
   = note: `#[warn(unused_must_use)]` (part of `#[warn(unused)]`) on by default
help: use `let _ = ...` to ignore the resulting value
   |
10 |     let _ = io::stdin().read_line(&mut guess);
   |     +++++++

warning: `guessing_game` (bin "guessing_game") generated 1 warning
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.59s

Rust memperingatkan bahwa Anda belum menggunakan nilai Result yang dikembalikan dari read_line, menandakan bahwa program belum menangani kemungkinan kesalahan.

Cara yang benar untuk menekan peringatan adalah benar-benar menulis kode penanganan kesalahan, tetapi dalam kasus kami kami hanya ingin program ini berhenti saat masalah terjadi, jadi kami bisa menggunakan expect. Anda akan belajar tentang pemulihan dari kesalahan di Bab 9.

Mencetak Nilai dengan Placeholder println!

Selain tanda kurung kurawal penutup, hanya ada satu baris lagi untuk dibahas dalam kode sejauh ini:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

Baris ini mencetak string yang kini berisi masukan pengguna. Set {} tanda kurung kurawal adalah placeholder: Anggap {} sebagai cengkerang kecil kepiting yang memegang nilai di tempatnya. Saat mencetak nilai variabel, nama variabel bisa masuk ke dalam tanda kurung kurawal. Saat mencetak hasil evaluasi ekspresi, tempatkan tanda kurung kurawal kosong di string format, lalu ikuti string format dengan daftar ekspresi yang dipisahkan koma untuk dicetak di setiap placeholder tanda kurung kurawal kosong dalam urutan yang sama. Mencetak variabel dan hasil ekspresi dalam satu pemanggilan println! akan terlihat seperti ini:

#![allow(unused)]
fn main() {
let x = 5;
let y = 10;

println!("x = {x} and y + 2 = {}", y + 2);
}

Kode ini akan mencetak x = 5 and y + 2 = 12.

Selanjutnya, kami perlu menghasilkan angka rahasia yang akan coba ditebak pengguna. Angka rahasia harus berbeda setiap kali agar permainan menyenangkan untuk dimainkan lebih dari sekali. Namun, tim Rust menyediakan crate rand dengan fungsionalitas tersebut.

Meningkatkan Fungsionalitas dengan Crate

Ingat bahwa crate adalah kumpulan berkas kode sumber Rust. Proyek yang kami bangun adalah crate biner, yaitu file yang dapat dieksekusi. Crate rand adalah crate pustaka (library crate), yang berisi kode yang dimaksudkan untuk digunakan di program lain dan tidak bisa dieksekusi sendiri.

Koordinasi Cargo terhadap crate eksternal adalah di mana Cargo benar-benar bersinar. Sebelum kami bisa menulis kode yang menggunakan rand, kami perlu mengubah berkas _Cargo.toml_ untuk menyertakan crate rand sebagai dependensi. Buka berkas itu sekarang dan tambahkan baris berikut di bagian bawah, di bawah header bagian [dependencies] yang Cargo buat untuk Anda. Pastikan untuk menentukan rand persis seperti yang kami tulis di sini, dengan nomor versi ini, atau contoh kode dalam tutorial ini mungkin tidak berfungsi:

Nama Berkas: Cargo.toml

[dependencies]
rand = "0.10.1"

Di berkas _Cargo.toml_, segala sesuatu yang mengikuti header adalah bagian dari bagian itu yang berlanjut hingga bagian lain dimulai. Di [dependencies], Anda memberitahu Cargo crate eksternal apa yang menjadi dependensi proyek Anda dan versi crate mana yang Anda butuhkan. Dalam kasus ini, kami menentukan crate rand dengan penentu versi semantik 0.10.1. Cargo memahami Semantic Versioning (kadang disebut SemVer), yaitu standar untuk penulisan nomor versi. Penentu 0.10.1 sebenarnya adalah singkatan untuk ^0.10.1, yang berarti versi apa pun yang setidaknya 0.10.1 tetapi di bawah 0.11.0.

Cargo menganggap versi-versi ini memiliki API publik yang kompatibel dengan versi 0.10.1, dan spesifikasi ini memastikan Anda akan mendapatkan rilis patch terbaru yang tetap akan kompilasi dengan kode di bab ini. Versi 0.11.0 atau lebih besar tidak dijamin memiliki API yang sama dengan yang digunakan contoh berikutnya.

Sekarang, tanpa mengubah kode apa pun, mari bangun proyek, seperti yang ditampilkan di Listing 2-2.

Anda mungkin melihat nomor versi yang berbeda (tapi semuanya akan kompatibel dengan kode, berkat SemVer!) dan baris yang berbeda (tergantung sistem operasi), dan baris-barisnya mungkin dalam urutan berbeda.

Ketika kita menyertakan dependensi eksternal, Cargo mengambil versi terbaru dari segala sesuatu yang dibutuhkan dependensi itu dari registry, yaitu salinan data dari Crates.io. Crates.io adalah tempat orang-orang di ekosistem Rust memposting proyek Rust sumber terbuka mereka untuk digunakan orang lain.

Setelah memperbarui registry, Cargo memeriksa bagian [dependencies] dan mengunduh crate yang tercantum yang belum diunduh. Dalam kasus ini, meskipun kami hanya mencantumkan rand sebagai dependensi, Cargo juga mengambil crate lain yang dibutuhkan rand untuk berfungsi. Setelah mengunduh crate-crate tersebut, Rust mengompilasinya dan kemudian mengompilasi proyek dengan dependensi yang tersedia.

Jika Anda segera menjalankan cargo build lagi tanpa membuat perubahan apa pun, Anda tidak akan mendapatkan keluaran apa pun selain baris Finished. Cargo tahu dia sudah mengunduh dan mengompilasi dependensi, dan Anda belum mengubah apa pun tentang mereka di berkas _Cargo.toml_ Anda. Cargo juga tahu bahwa Anda belum mengubah apa pun tentang kode Anda, jadi ia tidak mengompilasi ulang itu juga. Tanpa ada yang harus dilakukan, ia hanya keluar.

Jika Anda membuka berkas _src/main.rs_, membuat perubahan sekecil apa pun, dan lalu menyimpannya dan membangun lagi, Anda akan hanya melihat dua baris keluaran:

$ cargo build
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.13s

Baris-baris ini menunjukkan bahwa Cargo hanya memperbarui build dengan perubahan kecil Anda pada berkas _src/main.rs_. Dependensi Anda tidak berubah, jadi Cargo tahu dia bisa menggunakan kembali apa yang sudah diunduh dan dikompilasi untuk mereka.

Memastikan Build yang Dapat Direproduksi

Cargo memiliki mekanisme yang memastikan Anda bisa membangun artefak yang sama setiap kali Anda atau siapa pun membangun kode Anda: Cargo akan hanya menggunakan versi dependensi yang Anda tentukan sampai Anda menunjukkan sebaliknya. Misalnya, katakanlah minggu depan versi 0.10.2 dari crate rand keluar, dan versi itu mengandung perbaikan bug penting, tapi juga mengandung regresi yang akan merusak kode Anda. Untuk menangani ini, Rust membuat berkas _Cargo.lock_ saat pertama kali Anda menjalankan cargo build, sehingga kami sekarang memilikinya di direktori _guessing_game_.

Saat Anda membangun proyek untuk pertama kalinya, Cargo mengetahui semua versi dependensi yang memenuhi kriteria dan kemudian menuliskannya ke berkas _Cargo.lock_. Saat Anda membangun proyek Anda di masa depan, Cargo akan melihat berkas _Cargo.lock_ ada dan akan menggunakan versi yang ditentukan di sana alih-alih melakukan semua pekerjaan mengetahui versi lagi. Ini memungkinkan Anda memiliki build yang dapat direproduksi secara otomatis. Dengan kata lain, proyek Anda akan tetap di 0.10.1 sampai Anda secara eksplisit meningkatkan versinya, berkat berkas _Cargo.lock_. Karena berkas _Cargo.lock_ penting untuk build yang dapat direproduksi, ia sering dicek ke kontrol sumber bersama sisa kode di proyek Anda.

Memperbarui Crate untuk Mendapat Versi Baru

Saat Anda memang ingin memperbarui crate, Cargo menyediakan perintah update, yang akan mengabaikan berkas _Cargo.lock_ dan mengetahui semua versi terbaru yang memenuhi spesifikasi Anda di _Cargo.toml_. Cargo kemudian akan menuliskan versi-versi tersebut ke _Cargo.lock_. Jika tidak, secara default, Cargo hanya akan mencari versi yang lebih besar dari 0.10.1 dan kurang dari 0.11.0. Jika crate rand telah merilis dua versi baru 0.10.2 dan 0.999.0, Anda akan melihat hal berikut jika menjalankan cargo update:

$ cargo update
    Updating crates.io index
     Locking 1 package to latest Rust 1.96.0 compatible version
     Updating rand v0.10.1 -> v0.10.2 (available: v0.999.0)

Cargo mengabaikan rilis 0.999.0. Pada titik ini, Anda juga akan memperhatikan perubahan di berkas _Cargo.lock_ Anda mencatat bahwa versi crate rand yang Anda gunakan kini adalah 0.10.2. Untuk menggunakan rand versi 0.999.0 atau versi apa pun dalam seri 0.999.x, Anda harus memperbarui berkas _Cargo.toml_ agar terlihat seperti ini (jangan benar-benar membuat perubahan ini karena contoh-contoh berikut mengasumsikan Anda menggunakan rand 0.10):

[dependencies]
rand = "0.999.0"

Kali berikutnya Anda menjalankan cargo build, Cargo akan memperbarui registry crate yang tersedia dan mengevaluasi ulang kebutuhan rand Anda sesuai versi baru yang Anda tentukan.

Ada banyak lagi yang bisa dibahas tentang Cargo dan ekosistemnya, yang akan kami bahas di Bab 14, tapi untuk sekarang, itu saja yang perlu Anda ketahui. Cargo memudahkan penggunaan ulang pustaka, sehingga Rustacean mampu menulis proyek yang lebih kecil yang disusun dari sejumlah paket.

Menghasilkan Angka Acak

Mari mulai menggunakan rand untuk menghasilkan angka untuk ditebak. Langkah berikutnya adalah memperbarui _src/main.rs_, seperti yang ditampilkan di Listing 2-3.

Pertama, kami menambahkan baris use rand::prelude::*;. Modul prelude berisi bagian-bagian paling umum dari crate rand, dan use membuat item-item itu tersedia di ruang lingkup program kita.

Selanjutnya, kami menambahkan dua baris di tengah. Di baris pertama, kami memanggil fungsi rand::rng yang memberi kami generator angka acak tertentu yang akan kami gunakan: satu yang lokal ke thread eksekusi saat ini dan di-seed oleh sistem operasi. Kemudian, kami memanggil metode random_range pada generator angka acak. Metode ini didefinisikan oleh trait RngExt yang merupakan bagian dari modul rand::prelude yang kami bawa ke ruang lingkup dengan pernyataan use rand::prelude::*;. Metode random_range mengambil ekspresi range sebagai argumen dan menghasilkan angka acak dalam range tersebut. Jenis ekspresi range yang kami gunakan di sini berbentuk start..=end dan inklusif pada batas bawah dan atas, jadi kami perlu menentukan 1..=100 untuk meminta angka antara 1 dan 100.

Catatan: Anda tidak akan tahu saja apa yang harus dibawa ke ruang lingkup dan metode serta fungsi mana yang harus dipanggil dari crate, sehingga setiap crate memiliki dokumentasi dengan petunjuk untuk menggunakannya. Fitur menarik lain dari Cargo adalah menjalankan perintah cargo doc --open akan membangun dokumentasi yang disediakan oleh semua dependensi Anda secara lokal dan membukanya di peramban Anda. Jika Anda tertarik dengan fungsionalitas lain di crate rand, misalnya, jalankan cargo doc --open dan klik rand di bilah sisi kiri.

Membandingkan Tebakan dengan Angka Rahasia

Sekarang kami memiliki masukan pengguna dan angka acak, kami bisa membandingkan mereka. Langkah itu ditampilkan di Listing 2-4. Perhatikan bahwa kode ini belum akan kompilasi, sebagaimana akan kami jelaskan.

Pertama, kami menambahkan pernyataan use lain, membawa tipe bernama std::cmp::Ordering ke ruang lingkup dari pustaka standar. Tipe Ordering adalah enum lain dan memiliki varian Less, Greater, dan Equal. Ini adalah tiga hasil yang mungkin saat Anda membandingkan dua nilai.

Kemudian, kami menambahkan lima baris baru di bagian bawah yang menggunakan tipe Ordering. Metode cmp membandingkan dua nilai dan bisa dipanggil pada apa pun yang bisa dibandingkan. Ia mengambil referensi ke apa pun yang ingin Anda bandingkan: Di sini, ia membandingkan guess dengan secret_number. Kemudian, ia mengembalikan varian dari enum Ordering yang kami bawa ke ruang lingkup dengan pernyataan use. Kami menggunakan ekspresi match untuk memutuskan apa yang harus dilakukan berikutnya berdasarkan varian Ordering mana yang dikembalikan dari pemanggilan cmp dengan nilai-nilai di guess dan secret_number.

Ekspresi match terdiri dari arms (lengan). Sebuah arm terdiri dari pola untuk dicocokkan, dan kode yang harus dijalankan jika nilai yang diberikan ke match cocok dengan pola arm tersebut. Rust mengambil nilai yang diberikan ke match dan melihat melalui pola setiap arm secara berurutan. Pola dan konstruk match adalah fitur Rust yang powerful: Mereka memungkinkan Anda mengekspresikan berbagai situasi yang mungkin dihadapi kode Anda, dan memastikan Anda menangani semuanya. Fitur-fitur ini akan dibahas detail di Bab 6 dan Bab 19, masing-masing.

Mari jelajahi contoh dengan ekspresi match yang kami gunakan di sini. Katakanlah pengguna telah menebak 50 dan angka rahasia yang dihasilkan secara acak kali ini adalah 38.

Saat kode membandingkan 50 dengan 38, metode cmp akan mengembalikan Ordering::Greater karena 50 lebih besar dari 38. Ekspresi match mendapat nilai Ordering::Greater dan mulai memeriksa pola setiap arm. Ia melihat pola arm pertama, Ordering::Less, dan melihat bahwa nilai Ordering::Greater tidak cocok dengan Ordering::Less, jadi ia mengabaikan kode di arm tersebut dan berpindah ke arm berikutnya. Pola arm berikutnya adalah Ordering::Greater, yang memang cocok dengan Ordering::Greater! Kode terkait di arm itu akan diekseskusi dan mencetak Terlalu besar! ke layar. Ekspresi match berakhir setelah pencocokan pertama yang berhasil, jadi ia tidak akan melihat arm terakhir dalam skenario ini.

Inti kesalahan menyatakan ada mismatched types (ketidakcocokan tipe). Rust memiliki sistem tipe statis yang kuat. Namun, ia juga memiliki inferensi tipe. Saat kami menulis let mut guess = String::new(), Rust bisa menyimpulkan bahwa guess seharusnya String dan tidak memaksa kami menulis tipenya. secret_number, di sisi lain, adalah tipe angka. Beberapa tipe angka Rust bisa memiliki nilai antara 1 dan 100: i32, angka 32-bit; u32, angka 32-bit tanpa tanda; i64, angka 64-bit; serta lainnya. Kecuali ditentukan lain, Rust default ke i32, yang merupakan tipe secret_number kecuali Anda menambahkan informasi tipe di tempat lain yang menyebabkan Rust menyimpulkan tipe numerik yang berbeda. Alasan kesalahannya adalah Rust tidak bisa membandingkan string dan tipe angka.

Pada akhirnya, kami ingin mengubah String yang dibaca program sebagai masukan menjadi tipe angka sehingga kami bisa membandingkannya secara numerik dengan angka rahasia. Kami melakukannya dengan menambahkan baris ini ke badan fungsi main:

Nama Berkas: src/main.rs

use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    println!("The secret number is: {secret_number}");

    println!("Please input your guess.");

    // --snip--

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    let guess: u32 = guess.trim().parse().expect("Please type a number!");

    println!("You guessed: {guess}");

    match guess.cmp(&secret_number) {
        Ordering::Less => println!("Too small!"),
        Ordering::Greater => println!("Too big!"),
        Ordering::Equal => println!("You win!"),
    }
}

Barisnya adalah:

let guess: u32 = guess.trim().parse().expect("Please type a number!");

Kami membuat variabel bernama guess. Tunggu, bukankah program sudah punya variabel bernama guess? Memang, tapi Rust dengan membantu memungkinkan kami menybarkan (shadow) nilai sebelumnya guess dengan yang baru. Shadowing memungkinkan kami menggunakan kembali nama variabel guess alih-alih memaksa kami membuat dua variabel unik, seperti guess_str dan guess, misalnya. Kami akan membahas ini lebih detail di Bab 3, tapi untuk sekarang, ketahui bahwa fitur ini sering digunakan saat Anda ingin mengubah nilai dari satu tipe ke tipe lain.

Kami mengikat variabel baru ini ke ekspresi guess.trim().parse(). guess di ekspresi merujuk ke variabel guess asli yang berisi masukan sebagai string. Metode trim pada instance String akan menghapus whitespace di awal dan akhir, yang harus kami lakukan sebelum bisa mengubah string ke u32, yang hanya bisa berisi data numerik. Pengguna harus menekan enter untuk memenuhi read_line dan memasukkan tebakan mereka, yang menambahkan karakter newline ke string. Misalnya, jika pengguna mengetik 5 dan menekan enter, guess terlihat seperti ini: 5\n. \n mewakili “newline.” (Di Windows, menekan enter menghasilkan carriage return dan newline, \r\n.) Metode trim menghilangkan \n atau \r\n, menghasilkan hanya 5.

Metode parse pada string mengubah string ke tipe lain. Di sini, kami menggunakannya untuk mengubah dari string ke angka. Kami perlu memberitahu Rust tipe angka pasti yang kami inginkan dengan menggunakan let guess: u32. Titik dua (:) setelah guess memberitahu Rust kami akan mengannotasi tipe variabel. Rust memiliki beberapa tipe angka built-in; u32 yang terlihat di sini adalah integer 32-bit tanpa tanda. Ini pilihan default yang baik untuk angka positif kecil. Anda akan belajar tipe angka lain di Bab 3.

Selain itu, anotasi u32 dalam program contoh ini dan perbandingan dengan secret_number berarti Rust akan menyimpulkan bahwa secret_number juga seharusnya u32. Jadi, sekarang perbandingan akan antara dua nilai dengan tipe yang sama!

Metode parse hanya akan bekerja pada karakter yang secara logis bisa diubah menjadi angka dan jadi bisa dengan mudah menyebabkan kesalahan. Jika, misalnya, string berisi A👍%, tidak akan ada cara untuk mengubah itu ke angka. Karena bisa gagal, metode parse mengembalikan tipe Result, seperti yang dilakukan metode read_line (dibahas sebelumnya di “Menangani Potensi Kegagalan dengan Result”). Kami akan beperlakukan Result ini sama dengan menggunakan metode expect lagi. Jika parse mengembalikan varian Err Result karena tidak bisa membuat angka dari string, pemanggilan expect akan menghentikan game dan mencetak pesan yang kami berikan. Jika parse berhasil mengubah string ke angka, ia akan mengembalikan varian Ok dari Result, dan expect akan mengembalikan angka yang kami inginkan dari nilai Ok.

Keluar Setelah Tebakan Benar

Mari program game untuk keluar saat pengguna menang dengan menambahkan pernyataan break:

Nama Berkas: src/main.rs

use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    println!("The secret number is: {secret_number}");

    loop {
        println!("Please input your guess.");

        let mut guess = String::new();

        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");

        let guess: u32 = guess.trim().parse().expect("Please type a number!");

        println!("You guessed: {guess}");

        // --snip--

            Ordering::Less => println!("Too small!"),

                println!("You win!");
                break;
            }
        }
    }
}

Menambahkan baris break setelah Anda menang! membuat program keluar dari loop saat pengguna menebak angka rahasia dengan benar. Keluar dari loop juga berarti keluar dari program, karena loop adalah bagian terakhir dari main.

Menangani Masukan Tidak Valid

Untuk lebih menyempurnakan perilaku game, alih-alih membuat program berhenti (crash) saat pengguna memasukkan non-angka, mari buat game mengabaikan non-angka sehingga pengguna bisa terus menebak. Kami bisa melakukannya dengan mengubah baris di mana guess diubah dari String ke u32, seperti yang ditampilkan di Listing 2-5.

Kami beralih dari pemanggilan expect ke ekspresi match untuk beralih dari menghentikan program pada kesalahan ke menangani kesalahan. Ingat bahwa parse mengembalikan tipe Result dan Result adalah enum yang memiliki varian Ok dan Err. Kami menggunakan ekspresi match di sini, seperti yang kami lakukan dengan hasil Ordering dari metode cmp.

Jika parse mampu mengubah string ke angka dengan sukses, ia akan mengembalikan nilai Ok yang berisi angka hasilnya. Nilai Ok itu akan cocok dengan pola arm pertama, dan ekspresi match akan hanya mengembalikan nilai num yang dihasilkan parse dan ditempatkan di dalam nilai Ok. Angka itu akan berakhir tepat di tempat yang kami inginkan di variabel guess baru yang kami buat.

Jika parse tidak mampu mengubah string ke angka, ia akan mengembalikan nilai Err yang berisi lebih banyak informasi tentang kesalahan. Nilai Err tidak cocok dengan pola Ok(num) di arm pertama match, tapi cocok dengan pola Err(_) di arm kedua. Garis bawah, _, adalah nilai catch-all; dalam contoh ini, kami berkata kami ingin mencocokkan semua nilai Err, tidak peduli informasi apa yang mereka simpan di dalamnya. Jadi, program akan mengeksekusi kode arm kedua, continue, yang memberitahu program untuk pergi ke iterasi berikutnya dari loop dan meminta tebakan lain. Jadi, secara efektif, program mengabaikan semua kesalahan yang mungkin dihadapi parse!
