The Rust Programming Language

Sintaks Pola

Di bagian ini, kami mengumpulkan semua sintaks yang valid dalam pola dan membahas mengapa dan kapan Anda mungkin ingin menggunakan masing-masing.

Mencocokkan Literal

Seperti yang Anda lihat di Bab 6, Anda bisa mencocokkan pola terhadap literal secara langsung. Kode berikut memberikan beberapa contoh:

fn main() {
    let x = 1;

    match x {
        1 => println!("one"),
        2 => println!("two"),
        3 => println!("three"),
        _ => println!("anything"),
    }
}

Kode ini mencetak one karena nilai di x adalah 1. Sintaks ini berguna saat Anda ingin kode Anda melakukan tindakan jika ia mendapat nilai konkret tertentu.

Mencocokkan Variabel Bernama

Variabel bernama adalah pola irrefutable yang cocok dengan nilai apa pun, dan kami telah menggunakannya berkali-kali di buku ini. Akan tetapi, ada komplikasi saat Anda menggunakan variabel bernama di ekspresi match, if let, atau while let. Karena masing-masing dari jenis ekspresi ini memulai scope baru, variabel yang dideklarasikan sebagai bagian dari pola di dalam ekspresi-ekspresi ini akan menyembunyikan (shadow) variabel dengan nama yang sama di luar konstruksi tersebut, seperti halnya dengan semua variabel. Di Listing 19-11, kami mendeklarasikan variabel bernama x dengan nilai Some(5) dan variabel y dengan nilai 10. Kami kemudian membuat ekspresi match pada nilai x. Lihat pola di arm match dan println! di akhir, dan coba temukan apa yang akan dicetak kode ini sebelum menjalankan kode ini atau membaca lebih lanjut.

Mari jelajahi apa yang terjadi saat ekspresi match dijalankan. Pola di arm match pertama tidak cocok dengan nilai x yang didefinisikan, jadi kode berlanjut.

Pola di arm match kedua memperkenalkan variabel baru bernama y yang akan cocok dengan nilai apa pun di dalam nilai Some. Karena kami berada di scope baru di dalam ekspresi match, ini adalah variabel y baru, bukan y yang kami deklarasikan di awal dengan nilai 10. Pengikatan y baru ini akan cocok dengan nilai apa pun di dalam Some, yang kita miliki di x. Oleh karena itu, y baru ini terikat ke nilai internal Some di x. Nilai tersebut adalah 5, jadi ekspresi untuk arm itu dieksekusi dan mencetak Matched, y = 5.

Jika x bernilai None alih-alih Some(5), pola di dua arm pertama tidak akan cocok, jadi nilai akan cocok dengan underscore. Kami tidak memperkenalkan variabel x di pola arm underscore, jadi x di ekspresi tetap x luar yang tidak disembunyikan. Dalam kasus hipotetis ini, match akan mencetak Default case, x = None.

Saat ekspresi match selesai, scopenya berakhir, dan begitu juga scope y dalam. println! terakhir menghasilkan at the end: x = Some(5), y = 10.

Untuk membuat ekspresi match yang membandingkan nilai x dan y luar, bukannya memperkenalkan variabel baru yang menyembunyikan y yang sudah ada, kami perlu menggunakan match guard kondisional sebagai gantinya. Kami akan membahas match guard nanti di bagian “Menambahkan Kondisional dengan Match Guards”.

Mencocokkan Beberapa Pola

Di ekspresi match, Anda bisa mencocokkan beberapa pola menggunakan sintaks |, yang merupakan operator or pola. Misalnya, dalam kode berikut, kami mencocokkan nilai x terhadap arm match, yang pertama memiliki opsi or, artinya jika nilai x cocok dengan salah satu nilai di arm tersebut, kode arm itu akan dijalankan:

#![allow(unused)]
fn main() {
{{#rustdoc_include ../listings/ch19-patterns-and-matching/no-listing-02-multiple_patterns/src/main.rs:here}}
}

Kode ini mencetak one or two.

Mencocokkan Range Nilai dengan ..=

Sintaks ..= memungkinkan kami mencocokkan range nilai inklusif. Dalam kode berikut, saat pola cocok dengan salah satu nilai di dalam range yang diberikan, arm itu akan dieksekusi:

fn main() {
    let x = 5;

    match x {
        1..=5 => println!("one through five"),
        _ => println!("something else"),
    }
}

Jika x adalah 1, 2, 3, 4, atau 5, arm pertama akan cocok. Sintaks ini lebih nyaman untuk nilai match banyak dibanding menggunakan operator | untuk mengekspresikan ide yang sama; jika kami menggunakan |, kami harus menentukan 1 | 2 | 3 | 4 | 5. Menentukan range jauh lebih singkat, terutama jika kami ingin mencocokkan, katakanlah, angka apa pun antara 1 dan 1.000!

Compiler memeriksa bahwa range tidak kosong pada waktu kompilasi, dan karena satu-satunya tipe yang Rust bisa tentukan apakah range kosong atau tidak adalah char dan nilai numerik, range hanya diizinkan dengan nilai numerik atau char.

Berikut contoh menggunakan range nilai char:

fn main() {
    let x = 'c';

    match x {
        'a'..='j' => println!("early ASCII letter"),
        'k'..='z' => println!("late ASCII letter"),
        _ => println!("something else"),
    }
}

Rust bisa tahu bahwa 'c' berada dalam range pola pertama dan mencetak early ASCII letter.

Mendestrukturisasi untuk Memecah Nilai

Kami juga bisa menggunakan pola untuk mendestrukturisasi struct, enum, dan tuple untuk menggunakan bagian-bagian berbeda dari nilai ini. Mari jelajahi masing-masing nilai.

Struct

Listing 19-12 menunjukkan struct Point dengan dua field, x dan y, yang bisa kami pecah menggunakan pola dengan pernyataan let.

Kode ini membuat variabel a dan b yang cocok dengan nilai field x dan y dari struct p. Contoh ini menunjukkan bahwa nama variabel di pola tidak harus cocok dengan nama field struct. Akan tetapi, biasa mencocokkan nama variabel ke nama field untuk memudahkan mengingat variabel mana yang berasal dari field mana. Karena penggunaan ini umum, dan karena menulis let Point { x: x, y: y } = p; mengandung banyak duplikasi, Rust punya singkatan untuk pola yang cocok dengan field struct: Anda hanya perlu mencantumkan nama field struct, dan variabel yang dibuat dari pola akan memiliki nama yang sama. Listing 19-13 berperilaku sama seperti kode di Listing 19-12, tapi variabel yang dibuat di pola let adalah x dan y alih-alih a dan b.

Kode ini membuat variabel x dan y yang cocok dengan field x dan y dari variabel p. Hasilnya adalah variabel x dan y berisi nilai dari struct p.

Kami juga bisa mendestrukturisasi dengan nilai literal sebagai bagian dari pola struct bukunya membuat variabel untuk semua field. Melakukannya memungkinkan kami menguji beberapa field untuk nilai tertentu sambil membuat variabel untuk mendestrukturisasi field lainnya.

Di Listing 19-14, kami memiliki ekspresi match yang memisahkan nilai Point menjadi tiga kasus: titik yang berada langsung di sumbu x (yang benar saat y = 0), di sumbu y (x = 0), atau di keduanya tidak.

Arm pertama akan cocok dengan titik apa pun yang berada di sumbu x dengan menentukan bahwa field y cocok jika nilainya cocok dengan literal 0. Pola tetap membuat variabel x yang bisa kami gunakan di kode untuk arm ini.

Demikian pula, arm kedua cocok dengan titik apa pun di sumbu y dengan menentukan bahwa field x cocok jika nilainya 0 dan membuat variabel y untuk nilai field y. Arm ketiga tidak menentukan literal apa pun, jadi ia cocok dengan Point manapun lainnya dan membuat variabel untuk field x dan y keduanya.

Dalam contoh ini, nilai p cocok dengan arm kedua atas kebetulan x berisi 0, jadi kode ini akan mencetak On the y axis at 7.

Ingat bahwa ekspresi match berhenti memeriksa arm begitu ia menemukan pola yang pertama cocok, jadi meski Point { x: 0, y: 0 } berada di sumbu x dan sumbu y, kode ini hanya akan mencetak On the x axis at 0.

Enum

Kami telah mendestrukturisasi enum di buku ini (misalnya, Listing 6-5 di Bab 6), tapi kami belum secara eksplisit membahas bahwa pola untuk mendestrukturisasi enum sesuai dengan cara data yang tersimpan di dalam enum didefinisikan. Sebagai contoh, di Listing 19-15, kami menggunakan enum Message dari Listing 6-2 dan menulis match dengan pola yang akan mendestrukturisasi setiap nilai internal.

Kode ini akan mencetak Change color to red 0, green 160, and blue 255. Coba ubah nilai msg untuk melihat kode dari arm lain berjalan.

Untuk varian enum tanpa data apa pun, seperti Message::Quit, kami tidak bisa mendestrukturisasi nilai lebih lanjut. Kami hanya bisa cocok pada literal Message::Quit, dan tidak ada variabel di pola tersebut.

Untuk varian enum seperti struct, seperti Message::Move, kami bisa menggunakan pola mirip dengan pola yang kami tentukan untuk mencocokkan struct. Setelah nama varian, kami menempatkan kurung kurawal dan kemudian mencantumkan field dengan variabel sehingga kami memecah potongan-potongan untuk digunakan di kode arm ini. Di sini kami menggunakan bentuk singkat seperti yang kami lakukan di Listing 19-13.

Untuk varian enum seperti tuple, seperti Message::Write yang menampung tuple dengan satu elemen dan Message::ChangeColor yang menampung tuple dengan tiga elemen, polanya mirip dengan pola yang kami tentukan untuk mencocokkan tuple. Jumlah variabel di pola harus cocok dengan jumlah elemen di varian yang kami cocokkan.

Struct dan Enum Bersarang

Sejauh ini, contoh-contoh kami semua mencocokkan struct atau enum satu level dalam, tapi pencocokan bisa bekerja pada item bersarang juga! Misalnya, kami bisa refactor kode di Listing 19-15 untuk mendukung warna RGB dan HSV di pesan ChangeColor, seperti yang ditampilkan di Listing 19-16.

Pola arm pertama di ekspresi match cocok dengan varian enum Message::ChangeColor yang berisi varian Color::Rgb; lalu, pola mengikat ke tiga nilai i32 internal. Pola arm kedua juga cocok dengan varian enum Message::ChangeColor, tapi enum internal cocok Color::Hsv sebagai gantinya. Kami bisa menentukan kondisi kompleks ini dalam satu ekspresi match, meski dua enum terlibat.

Struct dan Tuple

Kami bisa mencampur, mencocokkan, dan menyingkat pola destrukturisasi dengan cara yang lebih kompleks lagi. Contoh berikut menunjukkan destrukturisasi yang rumit di mana kami menyingkat struct dan tuple di dalam tuple dan mendestrukturisasi semua nilai primitif keluar:

fn main() {
    struct Point {
        x: i32,
        y: i32,
    }

    let ((feet, inches), Point { x, y }) = ((3, 10), Point { x: 3, y: -10 });
}

Kode ini memungkinkan kami memecah tipe kompleks ke bagian komponennya sehingga kami bisa menggunakan nilai yang kami minati secara terpisah.

Mendestrukturisasi dengan pola adalah cara nyaman untuk menggunakan potongan nilai, seperti nilai dari setiap field di struct, secara terpisah satu sama lain.

Mengabaikan Nilai dalam Pola

Anda telah melihat bahwa kadang berguna untuk mengabaikan nilai dalam pola, seperti di arm terakhir match, untuk mendapatkan catch-all yang tidak benar-benar melakukan apa pun tapi mengakui semua nilai mungkin yang tersisa. Ada beberapa cara mengabaikan seluruh nilai atau bagian nilai dalam pola: menggunakan pola _ (yang sudah Anda lihat), menggunakan pola _ di dalam pola lain, menggunakan nama yang diawali underscore, atau menggunakan .. untuk mengabaikan sisa bagian nilai. Mari jelajahi bagaimana dan mengapa menggunakan masing-masing pola ini.

Seluruh Nilai dengan _

Kami telah menggunakan underscore sebagai pola wildcard yang akan cocok dengan nilai apa pun tapi tidak mengikat ke nilai itu. Ini khususnya berguna sebagai arm terakhir di ekspresi match, tapi kami juga bisa menggunakannya di pola apa pun, termasuk parameter fungsi, seperti yang ditampilkan di Listing 19-17.

Kode ini akan sepenuhnya mengabaikan nilai 3 yang diteruskan sebagai argumen pertama, dan akan mencetak This code only uses the y parameter: 4.

Dalam kebanyakan kasus saat Anda tidak lagi butuh parameter fungsi tertentu, Anda akan mengubah tanda tangan sehingga tidak mencakup parameter yang tidak digunakan. Mengabaikan parameter fungsi bisa sangat berguna di kasus di mana, misalnya, Anda mengimplementasikan trait saat Anda butuh tanda tangan tipe tertentu tapi badan fungsi dalam implementasi Anda tidak butuh salah satu parameternya. Anda kemudian menghindari peringatan compiler soal parameter fungsi yang tidak digunakan, seperti yang akan terjadi jika Anda menggunakan nama sebagai gantinya.

Bagian Nilai dengan _ Bersarang

Kami juga bisa menggunakan _ di dalam pola lain untuk mengabaikan hanya bagian dari nilai, misalnya, saat kami ingin menguji hanya bagian dari nilai tapi tidak butuh bagian lainnya di kode yang koresponden yang ingin kami jalankan. Listing 19-18 menunjukkan kode yang bertanggung jawab mengelola nilai setting. Persyaratan bisnis adalah pengguna tidak boleh menimpa kustomisasi existing dari setting tapi bisa unset setting dan memberinya nilai jika saat ini unset.

Kode ini akan mencetak Can't overwrite an existing customized value dan lalu setting is Some(5). Di arm match pertama, kami tidak butuh mencocokkan atau menggunakan nilai di dalam varian Some manapun, tapi kami butuh menguji kasus saat setting_value dan new_setting_value keduanya varian Some. Dalam kasus itu, kami mencetak alasan tidak mengubah setting_value, dan ia tidak diubah.

Di semua kasus lain (jika setting_value atau new_setting_value adalah None) diekspresikan oleh pola _ di arm kedua, kami ingin mengizinkan new_setting_value menjadi setting_value.

Kami juga bisa menggunakan underscore di beberapa tempat dalam satu pola untuk mengabaikan nilai khusus. Listing 19-19 menunjukkan contoh mengabaikan nilai kedua dan keempat dalam tuple lima item.

Kode ini akan mencetak Some numbers: 2, 8, 32, dan nilai 4 dan 16 akan diabaikan.

Variabel Tidak Digunakan dengan Menamainya Diawali _

Jika Anda membuat variabel tapi tidak menggunakannya di mana pun, Rust biasanya akan mengeluarkan peringatan karena variabel yang tidak digunakan bisa jadi bug. Akan tetapi, kadang berguna untuk bisa membuat variabel yang tidak akan Anda gunakan, misalnya saat Anda membuat prototipe atau baru memulai proyek. Dalam situasi ini, Anda bisa memberitahu Rust untuk tidak memperingatkan Anda soal variabel tidak digunakan dengan menamai variabel diawali underscore. Di Listing 19-20, kami membuat dua variabel tidak digunakan, tapi saat kami mengompilasi kode ini, kami seharusnya hanya mendapat peringatan tentang salah satunya.

Di sini, kami mendapat peringatan soal variabel y yang tidak digunakan, tapi kami tidak mendapat peringatan soal _x.

Perhatikan bahwa ada perbedaan halus antara menggunakan hanya _ dan menggunakan nama yang diawali underscore. Sintaks _x tetap mengikat nilai ke variabel, sedangkan _ tidak mengikat sama sekali. Untuk menunjukkan kasus di mana perbedaan ini penting, Listing 19-21 akan memberikan error.

Kami akan menerima error karena nilai s akan tetap di-move ke _s, yang mencegah kami menggunakan s lagi. Akan tetapi, menggunakan underscore saja tidak pernah mengikat ke nilai. Listing 19-22 akan kompilasi tanpa error karena s tidak di-move ke _.

Kode ini berfungsi dengan baik karena kami tidak pernah mengikat s ke apa pun; ia tidak di-move.

Sisa Bagian Nilai dengan ..

Dengan nilai yang punya banyak bagian, kami bisa menggunakan sintaks .. untuk menggunakan bagian-bagian spesifik dan mengabaikan sisanya, menghindari kebutuhan mencantumkan underscore untuk setiap nilai yang diabaikan. Pola .. mengabaikan bagian-bagian dari nilai yang kami tidak secara eksplisit cocokkan di sisa pola. Di Listing 19-23, kami memiliki struct Point yang menampung koordinat dalam ruang tiga dimensi. Di ekspresi match, kami ingin beroperasi hanya pada koordinat x dan mengabaikan nilai di field y dan z.

Kami mencantumkan nilai x lalu hanya menyertakan pola ... Ini lebih cepat dari harus mencantumkan y: _ dan z: _, terutama saat kami bekerja dengan struct yang punya banyak field di situasi di mana hanya satu atau dua field yang relevan.

Sintaks .. akan expand ke sebanyak nilai yang dibutuhkan. Listing 19-24 menunjukkan cara menggunakan .. dengan tuple.

Dalam kode ini, nilai pertama dan terakhir dicocokkan dengan first dan last. .. akan cocok dan mengabaikan semua di antara mereka.

Akan tetapi, penggunaan .. harus tidak ambigu. Jika tidak jelas nilai mana yang dimaksudkan untuk dicocokkan dan mana yang seharusnya diabaikan, Rust akan memberi error. Listing 19-25 menunjukkan contoh penggunaan .. secara ambigu, jadi tidak akan kompilasi.

Saat kami mengompilasi contoh ini, kami mendapat error ini:

$ cargo run
   Compiling patterns v0.1.0 (file:///projects/patterns)
error: `..` can only be used once per tuple pattern
 --> src/main.rs:5:22
  |
5 |         (.., second, ..) => {
  |          --          ^^ can only be used once per tuple pattern
  |          |
  |          previously used here

error: could not compile `patterns` (bin "patterns") due to 1 previous error

Rust tidak mungkin menentukan berapa banyak nilai di tuple yang harus diabaikan sebelum mencocokkan nilai dengan second dan lalu berapa banyak nilai lagi yang diabaikan setelahnya. Kode ini bisa berarti kami ingin mengabaikan 2, mengikat second ke 4, dan lalu mengabaikan 8, 16, dan 32; atau bahwa kami ingin mengabaikan 2 dan 4, mengikat second ke 8, dan lalu mengabaikan 16 dan 32; dan seterusnya. Nama variabel second tidak berarti apa pun khusus bagi Rust, jadi kami mendapat error compiler karena menggunakan .. di dua tempat seperti ini ambigu.

Menambahkan Kondisional dengan Match Guards

Sebuah match guard adalah kondisi if tambahan, yang ditentukan setelah pola di arm match, yang juga harus cocok agar arm itu dipilih. Match guard berguna untuk mengekspresikan ide yang lebih kompleks dari yang diizinkan pola saja. Perhatikan, bagaimanpun, bahwa mereka hanya tersedia di ekspresi match, bukan if let atau ekspresi while let.

Kondisi bisa menggunakan variabel yang dibuat di pola. Listing 19-26 menunjukkan match di mana arm pertama punya pola Some(x) dan juga match guard if x % 2 == 0 (yang akan true jika angka genap).

Contoh ini akan mencetak The number 4 is even. Saat num dibandingkan dengan pola di arm pertama, ia cocok karena Some(4) cocok Some(x). Lalu, match guard memeriksa apakah sisa bagi x dibagi 2 sama dengan 0, dan karena demikian, arm pertama dipilih.

Jika num adalah Some(5), match guard di arm pertama akan false karena sisa 5 dibagi 2 adalah 1, yang tidak sama dengan 0. Rust akan lalu ke arm kedua, yang akan cocok karena arm kedua tidak punya match guard dan oleh karena itu cocok dengan varian Some apa pun.

Tidak ada cara untuk mengekspresikan kondisi if x % 2 == 0 dalam pola, jadi match guard memberi kami kemampuan mengekspresikan logika ini. Kelemahan ekspresivitas tambahan ini adalah compiler tidak mencoba memeriksa exhaustiveness saat ekspresi match guard terlibat.

Saat membahas Listing 19-11, kami menyebutkan bahwa kami bisa menggunakan match guard untuk memecahkan masalah shadowing pola kami. Ingat bahwa kami membuat variabel baru di dalam pola di ekspresi match alih-alih menggunakan variabel di luar match. Variabel baru itu berarti kami tidak bisa menguji terhadap nilai variabel luar. Listing 19-27 menunjukkan bagaimana kami bisa menggunakan match guard untuk memperbaiki masalah ini.

Kode ini kini akan mencetak Default case, x = Some(5). Pola di arm match kedua tidak memperkenalkan variabel baru y yang akan menyembunyikan y luar, artinya kami bisa menggunakan y luar di match guard. Alih-alih menentukan pola sebagai Some(y), yang akan menyembunyikan y luar, kami menentukannya sebagai Some(n). Ini membuat variabel baru n yang tidak menyembunyikan apa pun karena tidak ada variabel n di luar match.

Match guard if n == y bukan pola dan oleh karena itu tidak memperkenalkan variabel baru. y ini adalah y luar bukannya y baru yang menyembunyikannya, dan kami bisa mencari nilai yang punya nilai sama dengan y luar dengan membandingkan n ke y.

Anda juga bisa menggunakan operator or | di match guard untuk menentukan beberapa pola; kondisi match guard akan berlaku untuk semua pola. Listing 19-28 menunjukkan precedence saat menggabungkan pola yang menggunakan | dengan match guard. Bagian penting dari contoh ini adalah bahwa match guard if y berlaku untuk 4, 5, dan 6, meski mungkin terlihat seperti if y hanya berlaku untuk 6.

Kondisi match menyatakan arm hanya cocok jika nilai x sama dengan 4, 5, atau 6 dan jika y adalah true. Saat kode ini dijalankan, pola arm pertama cocok karena x adalah 4, tapi match guard if y adalah false, jadi arm pertama tidak dipilih. Kode berlanjut ke arm kedua, yang cocok, dan program ini mencetak no. Alasannya adalah kondisi if berlaku untuk seluruh pola 4 | 5 | 6, bukan hanya nilai terakhir 6. Dengan kata lain, precedence match guard terkait pola berperilaku seperti ini:

(4 | 5 | 6) if y => ...

bukan ini:

4 | 5 | (6 if y) => ...

Setelah menjalankan kode, perilaku precedence terlihat: Jika match guard hanya diterapkan ke nilai terakhir dalam daftar nilai yang dispesifikasikan menggunakan operator |, arm akan cocok, dan program akan mencetak yes.

Menggunakan Binding @

Operator at @ memungkinkan kami membuat variabel yang menampung nilai pada saat yang sama kami menguji nilai itu untuk pencocokan pola. Di Listing 19-29, kami ingin menguji bahwa field id dari Message::Hello berada dalam range 3..=7. Kami juga ingin mengikat nilai ke variabel id sehingga kami bisa menggunakannya di kode yang terkait dengan arm.

Contoh ini akan mencetak Found an id in range: 5. Dengan menentukan id @ sebelum range 3..=7, kami menangkap nilai apa pun yang cocok dengan range dalam variabel bernama id sambil juga menguji bahwa nilai cocok dengan pola range.

Di arm kedua, di mana kami hanya memiliki range yang ditentukan di pola, kode yang terkait dengan arm tidak punya variabel yang berisi nilai aktual dari field id. Nilai field id bisa jadi 10, 11, atau 12, tapi kode yang pergi dengan pola itu tidak tahu mana di antaranya. Kode pola tidak bisa menggunakan nilai dari field id karena kami tidak menyimpan nilai id di variabel.

Di arm terakhir, di mana kami menentukan variabel tanpa range, kami punya nilai yang tersedia untuk digunakan di kode arm dalam variabel bernama id. Alasannya adalah kami telah menggunakan sintaks singkat field struct. Tapi kami tidak menerapkan pengujian apa pun ke nilai di field id di arm ini, seperti yang kami lakukan dengan dua arm pertama: Nilai apa pun akan cocok dengan pola ini.

Menggunakan @ memungkinkan kami menguji nilai dan menyimpannya di variabel dalam satu pola.

Ringkasan

Pola Rust sangat berguna dalam membedakan jenis data yang berbeda. Saat digunakan di ekspresi match, Rust memastikan bahwa pola Anda menutupi setiap nilai mungkin, atau program Anda tidak akan kompilasi. Pola di pernyataan let dan parameter fungsi membuat konstruksi tersebut lebih berguna, memungkinkan destrukturisasi nilai ke bagian-bagian lebih kecil dan menetapkan bagian-bagian itu ke variabel. Kami bisa membuat pola sederhana atau kompleks untuk memenuhi kebutuhan kami.
